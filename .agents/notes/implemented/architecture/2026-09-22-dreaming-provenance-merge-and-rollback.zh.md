# Agent Note: Dreaming 为出处设门、合并复述，并从自己的前像回滚一次提升

Status: implemented

[English](2026-09-22-dreaming-provenance-merge-and-rollback.md) | 中文

## 问题

§53 的 Dreaming 一行要求出处门、合并/取代，以及基于前像的回滚；§19 说明了它们的含义：提升使用分数、回放频次与查询多样性三道门；不可信或系统派生的候选被挡在持久提升路径之外；被接受的改写保留前像与可供审阅的 dream 报告。

本包此前拥有其中前半部分，其余一概没有。`dsh-evolution-dreaming`（见[梦境决策](2026-09-13-dreaming-and-reranker-decision.zh.md)）用六信号复合分为每个已暂存候选打分，并提升通过三道数值门的候选；它自己的 README 则直言另外两处缺口：提升"在被读取之前是死胡同"，且没有任何东西把已提升的 dream 注入模型上下文。除此之外：

- Light 从两个认知地位不同的来源暂存候选——feedback 接缝记录的失败工具结果，与记忆存储日常日志里的情景笔记——而 Deep 一视同仁，于是模型抽取出的笔记与被 harness 亲眼看着失败的记录一样能被提升。
- 提升的身份就是它规范化后的陈述，因此每一轮重新报告同一失败都会再次被同一套门限量度，而一条已提升陈述的同义转述则会成为第二条持久条目。没有任何东西让被更正的旧陈述退役，记录里也没有这两种情形的任何标记。
- 每一轮 deep 都整体重写提升数组，只有最新状态留存：一次衰减清扫或一次错误提升都无路可退。

## 决定

**出处是第一道门，且它信任的来源被点名。** 候选的观察现在携带出处：对 feedback 接缝聚合出的失败 `tool/result` 事件记为 `attributed`，因为它在消息旁记录了工具名与会话；对情景笔记记为 `unattributed`，因为记忆存储只记录文本、日期与时刻，没有任何能标识作者的字段。`decidePromotion` 在比较任何阈值之前就按名拒绝不可溯源的候选（`unattributed-provenance`），因此无法溯源的候选不能靠高分抵达持久路径。只要有一条被观察到的观察，就为它所并入的候选作保，因此复述某条已记录失败的笔记仍会为那条失败增加证据——`mergeProvenance` 让 `attributed` 具有吸收性——而仅靠笔记的候选永远无法提升。

**一条关系规则同时决定合并与取代。** `relateNarrative` 把过门候选与该作用域仍会作答的叙事相比，且只与同名工具的叙事相比：工具不同的两次失败无论措辞多像都是两个主题。概念重合度——也就是相关性信号所读的同一套词面度量——把关系分为 `identical`（记录本就作答的身份，含它已并入的某个措辞）、达到 `mergeOverlap` 的 `restates`、以及落在 `supersedeOverlap` 与 `mergeOverlap` 之间的 `corrects`。复述会并入它所复述的叙事，并列出被并入的措辞，因此记录不收集近似重复，而规范陈述、提升时刻与证据都原位不动。更正会装入一条新叙事，并给前任标记上取代它的身份与时刻；前任保留自己的位置与证据，但不再回答任何东西——这正是 `evolution-graph` 对已退役声明所用的规则。候选是与同一轮已写入的叙事相比对的，因此同时到达的两条复述只产生一条叙事。每个本会提升的候选都必须先过门，因此未通过阈值的更正不会让任何东西退役。

**账本及其回滚遵循 curator 的形态。** 每一轮改变提升集合的遍历都追加一条条目，条目持有它替换掉的那份提升数组（`before`）、它装入的数组（`after`）、动作主体、动作种类，以及这一轮做了什么——新增、并入、退役、丢弃。与在磁盘上按内容寻址 blob 的 `evolution-curator` 不同，这里的条目内联持有前像：dreaming 的持久状态本身就是一条存储域记录，因此记录就是自己的 blob 存储，前像是在写入与读取之间不可能丢失的，也不必为一个包的状态新增第二套存储机制。`rollback(scope, entryId)` 在写入前先对未知身份大声失败，随后原样恢复前像，报告它送回作答状态的各条叙事，并追加自己的条目——这使回滚与被它撤销的那一轮同样可逆。账本由 `maxLedgerEntries` 限定，保留最新的若干条，因此长寿命作用域拥有的是一段回滚窗口，而不是它跑过的每一轮。

**读取一半仍然延期，README 写明了原因。** 唯一把作用域记忆送到模型面前的消费方是 `dsh-evolution-memory-context`：它在自己的字节预算与摘要契约下，用记忆存储的若干精修家族渲染简报；dream 不属于这些家族，把它注入会改变另一个包的提示面，并且它新增的文本需要一条可记录在日志里的会话事件。本次改动提供的替代物是消费方本会调用的那道接缝——`promotions(scope)` 只回答未被更正退役的叙事——以及对缺失之处的如实陈述。

**新增的一切都是经校验的配置字段。** `mergeOverlap`、`supersedeOverlap`、`maxRestatements` 与 `maxLedgerEntries` 加入既有的阈值；`resolveConfig` 会拒绝高于 `mergeOverlap` 的 `supersedeOverlap`，那会让每个相关候选都成为复述，并使更正无法让任何东西退役。

## 考虑过的替代方案

**因为一条情景笔记经人批准进入日志就信任它。** 否决：情景层只记录日期、文本与时刻。评审器的抽取会写这些笔记，用户也会写，而存储无法区分两者，因此一条"已批准"的笔记仍是无人能作保的文本。信任边界只能落在记录下出处的地方，也就是 feedback 接缝观察到的工具结果。

**只要某条笔记沾过就拒绝提升，而不只是拒绝纯笔记候选。** 否决：复述某条已记录失败的笔记，正是回放与多样性门试图度量的独立上下文证据，丢弃它会抹掉笔记路径仅存的作用。因此出处是候选的属性，并从其观察向上吸收。

**像 `evolution-graph` 用 `supersedes` 那样，由声明的关系统定复述与更正。** 否决：该图的关系来自模型抽取的批次，而这条路径在构造上不调用模型。词面规则付出了有据可查的代价——没有共享词汇的转述会被当作新叙事——换来的是无需任何提供方即可检验的判定。

**两条规则，一条管并入，一条管退役。** 否决：两个问题有相同的输入与相同的答案形态，而同一个重合度上的两个阈值意味着对同一对陈述有两次意见不一的机会。`relateNarrative` 返回一条关系及决定它的重合度，`evolveNarratives` 执行该关系点名的写入。

**完全照 curator 的存法，在文件系统上按内容寻址存前像 blob。** 否决：curator 的状态是技能树加 JSONL 账本，因此需要 blob 目录；dreaming 的状态是一条域记录，在它旁边再放一套文件系统存储就成了第二套持久化机制、第二条清理路径、以及第二个必须与取代它的记录保持一致的物件。前像数组随作废它的那条条目一起行走。

**把门的拒绝持久记录在叙事上。** 否决：REM 在 deep 阶段运行之前就写好叙事，因此一份持久拒绝清单会要求 deep 阶段重写前一阶段的记录。拒绝由阶段报告返回，并在账本条目的计数中汇总——那正是操作者在跑完一轮后查看的地方。

**通过把 dreams 渲染进记忆简从来接上读取一半。** 目前否决：简报的预算与摘要属于 `dsh-evolution-memory-context`，被注入的文本会是一个新的模型可见面，需要自己的会话事件，而这些材料大体上对话记录本就展示——被提升的陈述复述的是模型已经见过的失败。接缝已经存在；注入属于拥有简报的那个包的决定。

## 后果

- **纯笔记候选不再能提升**，这是对已发布机制唯一可见的行为变化：本包 README 此前称跨天重复的笔记可以提升，那句话现在成了门的拒绝。笔记仍会暂存、仍为六信号添加上下文，也仍会强化 feedback 接缝同样报告过的失败。
- 提升写入按轮可逆：`rollback(scope, entryId)` 之后 `read(scope).promotions` 正是这一轮替换掉的那个数组，包括这一轮并入、退役或丢弃的任何叙事；而回滚自身也是一条账本条目。
- 持久记录每有一个发生变化的轮次就增加一条账本条目（由 `maxLedgerEntries` 限定），并在每条提升上增加四个字段：门的证据、它并入的复述、以及取代标记。每一个都带 zod 默认值，因此早于它们写下的记录照常打开，`evolution_dreams` 域仍停留在版本 1。
- 更正是新增一行而非一次改写：退役的叙事保留其身份、陈述、分数、信号与证据，只有取代字段说明它已被替换。想要实时集合的读者去要它（`promotions(scope)`）；想要完整来龙去脉的读者读记录。
- 本周期仍不发起任何模型调用、不新增提示词段落、不发布任何模型可见的新的持久面，因此 §58 的「记录而不强制」边界保持不变。

## 测试

`packages/evolution/evolution-dreaming/tests/narrative.spec.ts` 在无上下文的情况下覆盖各条纯规则：身份规范化、出处吸收、每道门的拒绝与接纳、三种关系加上已退役、不同工具与无关陈述的拒绝、最强重合度的选取，以及并入、上限、同一身份与取代这几种写入。`tests/dreaming.spec.ts` 在内存存储后端上驱动服务，覆盖必须依托上下文的那些行为：

- 纯笔记候选被按 `unattributed-provenance` 拒绝且不写任何东西，而同一文本以已记录工具结果出现时获得提升，且笔记观察被吸收进它的证据；
- 复述在提升它的同一轮里并入它所复述的叙事，只留一条条目并列出被并入的措辞；
- 更正后的陈述获得提升，其前任不再作答，但在记录中保留位置与证据，并点名取代它的对象；
- `rollback(scope, entryId)` 原样恢复前像数组，报告被送回作答状态的叙事，并记入一条反转条目——对它的回滚又能恢复回滚所替换的内容；
- 未知账本身份在写入任何东西之前失败，账本只保留最新的 `maxLedgerEntries` 轮；
- 阶段报告按名列出每道拒绝的门及其计数。

本包在 `src/` 上保持逐文件 100% 覆盖率。

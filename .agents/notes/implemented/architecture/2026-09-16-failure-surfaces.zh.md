# Agent Note: 变异算子的失败面

Status: implemented

[English](2026-09-16-failure-surfaces.md) | 中文

## Problem

`specs/evolutionary-harness-v11-deep-research.md` §30 要求变异引擎依据一份学到的先验——从失败模式到「哪些修法奏效」的映射——来选择算子，而不只是按配置顺序。优化器记录了每次运行测到的东西，却没有记录**是哪个算子产出了优胜正文**：[实验台账](2026-09-16-experiment-ledger-and-confidence.zh.md)存了优胜者的三元组与其正文摘要，而写出它的那个算子在运行返回时被丢弃了。没有这一事实就无法推导任何先验，而停滞检测器的切换——本身就是对失败的一种反应——也只能移除算子，永远无法偏好某个算子。

## Decision

**一个被记录的事实，一个推导出的排序，一个阈值。**

- **台账记录优胜者由哪个算子产出。** `ExperimentRecord.winnerOperator` 记录产出被晋级正文的算子，未晋级时为 `null`。运行的 draft 携带获胜的 `EvaluatedVariant` 而不是它的正文文本，于是该行不再为了读一个它本就持有的三元组而重新在候选里寻找优胜者。
- **失败面以证据的形态为键。** `failureSignature` 把证据转小写、把每一段数字折成单个 `#`、并压缩空白：`3 failures over 20 recorded loads` 与 `11 failures over 204 recorded loads` 是同一个失败。一次新的遥测读数所产生的计数器，恰恰就是那个否则会每跑一次就把同一个反复出现的失败模式拆到不同记录里的部分。
- **`operatorRecords` 针对一个签名按算子统计尝试、获胜与新鲜度**，数据来自某个作用域的行：每个产出过候选的算子记一次尝试，被运行晋级的候选所属算子记一次获胜，而新鲜度记给行里 `novelOperators` 列出的任何算子——即至少产出一条「说出了起始正文尚未包含的指令行」的候选的算子，该内容在选择之前以[新颖度](2026-09-16-optimizer-batch6.zh.md)衡量。它跳过从未走到评估的行，与台账的其他读者一致。
- **`orderPortfolio` 按该记录排序阵容**：在这个失败上赢过的算子排最前（胜率优先，并列时按配置顺序），这个失败没有合格记录的算子随后（按配置顺序），只在这里输过的算子排最后——其中至少说出过正文尚未包含内容的那些，排在只会重复它的那些之前，然后才是尝试次数多者优先。最后这条排序正是 §31 的新颖压力落在单次运行优化器能作用的地方：它无法二次奖励候选，但可以不再从那个一直复述正文的算子里抽取。顺序就是杠杆——`distributeCandidates` 按阵容顺序切分 `maxCandidates`，因此排在前面的算子拿走余数。
- **`priorMinTries`（默认 3）是证据下限。** 低于它，算子在那个失败上等同于从未见过，因此一次侥幸的胜利无法改变阵容顺序，先验在台账真正测到东西之前保持沉默。
- **停滞与先验按此顺序组合**：停滞把阵容收窄到近期窗口内没有产出候选的算子，先验再对留下来的阵容排序。先验绝不会把收窄过的阵容扩宽；没有记录的签名则完整保留配置顺序。

## Alternatives considered

- **按技能而非按失败统计的先验。** 否决：台账的行本就带着技能，但同一个技能的失败有不同成因，把它们平均会推荐「赢下最常见那个失败」的算子，而不是修好当下这个失败的算子。 Rejected: the ledger's rows already carry the skill, but a skill's failures have different causes, and averaging over them would recommend the operator that wins the most common failure rather than the one that repairs the failure at hand.
- **以精确的证据文本作为失败面的键。** 否决：默认证据内嵌遥测计数器，映射表会变成每个读数一条，永远攒不出算出一个比率所需的两三次尝试。折叠数字是能扛过一次重新读数的最小归一化，其代价写在 README 中——只在数字上不同的两个失败会共用一条记录。
- **显式的失败模式分类体系**（把证据解析成 `stale_context`、`tool_error` 等）。暂时否决：证据由调用方产生，而自由文本上的分类器要么是一份本仓库得长期维护的关键词表，要么是每次运行一次模型调用——而这一切只为给「排序阵容」这份先验服务。签名就是台账在不发明分类体系的前提下能支撑的那套分类。
- **老虎机式探索**（对算子臂做 UCB/Thompson，按固定比例探索未测过的算子）。暂时否决：晋级稀有且昂贵，某个作用域已有的行算出的比率本就是薄弱证据；而探索需要有目的地花掉评分运行，这与带预算上限的运行所做的承诺正好相反。这里的排序是先验而不是策略，`priorMinTries` 正是让它不要过早开口的东西。
- **把新鲜度当作量级而不是事实。** 否决：行记录的是哪些算子说出过新内容，而不是有多少，因为它所喂给的规则是「这个算子在这里到底说过什么没有」，而按算子的最大值就得为每个算子单独存一份才能回答。五十行里只说出一行的候选算作新鲜，这正是「它确实说了点什么」的诚实读法。
- **把获胜记给获胜运行阵容里的每个算子。** 否决：阵容是一起被测量的，全部记账会教先验「一个好阵容里最差的算子同样有效」——这是唯一会让先验变得有害的错误。
- **只在分选载荷里记录算子。** 否决：`/curator experiments` 读的是台账，而审计「哪个算子修好了什么」的人需要这一事实落在行上，而不是藏在作用域的分选条目里。

## Consequences

一次运行所抽取的阵容现在反映了台账为该失败测得的东西；每次晋级背后的算子是被记录的事实，而不再只是载荷里的细节；停滞切换也有了可以据以排序它保留算子的依据。代价写在包 README 中：先验按签名与作用域统计，而不是按技能；签名的数字折叠会合并只在数量级上不同的失败；一次运行只把获胜记给产出优胜候选的那个算子，因此一个产出「好但落败」候选的算子只得到一次尝试、没有获胜。

验证：95 个优化器测试，包括阵容跟随「compress 赢过、rewrite 输过」的先验、低于 `priorMinTries` 时保留配置顺序、计数器变动过的失败仍由修好它的算子领队，以及复述正文的算子在同场运行中落到加了一条规则的算子之后；另有针对 `failureSignature`、`operatorRecords` 与 `orderPortfolio` 每一个排序分支的纯测试。`packages/evolution/evolution-optimizer/src` 的语句、分支、函数与行覆盖率均为 100%。

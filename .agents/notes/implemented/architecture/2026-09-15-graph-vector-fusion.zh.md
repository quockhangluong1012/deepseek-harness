# Agent Note: 知识图谱获得生产者，并在 pre-step 简报中取得一席

Status: implemented

[English](2026-09-15-graph-vector-fusion.md) | 中文

## 问题

规范 §17 要求把向量检索（发现）与图谱检索（导航）融合。仓库已拥有除两部分之外的全部部件。

`dsh-evolution-graph` 拥有存储与查询 API——`observe`、`answer`、`expand`、`find`，并通过 `/graph` 读取——但没有任何生产环境的生产者：除测试外无人调用 `observe`，因此每张图永远为空。而且图谱不携带会话来源，因此遍历到达的实体无法与某条会话命中建立关联，除非凭空发明一种 schema 并不携带的链接。

`dsh-active-memory-context` 仅按相似度检索既往会话。挂在用户刚刚提到的实体上的会话，只有在其文本也与该轮次相似时才会浮现——邻近与连接是两种不同的关系，而此前只问了其中一种。

三条约束来自仓库而非规范。`packages/AGENTS.md` 要求可选服务通过 `ctx.get(name)` 获取；仅挂载存储的部署必须在没有模型时仍能加载图谱。仓库自己的融合辅助函数（`fuseSessionRankings`）已经定义了会话命中上的倒数排名融合，因此合并规则必须复用而非重新推导。并且每个 seam 都以结构化方式到达——本地接口加 `Reflect.get` 守卫——因此两个包都不依赖对方的包，只依赖其发布的形状。

## 决策

两半，一座桥。

**生产者。** 与 `dsh-evolution-heartbeat` 一起挂载时，`dsh-evolution-graph` 以 `intervalHours`（默认 6）注册任务 `evolution-graph-extract`。它随用户与助手消息的发布缓冲各作用域内这些消息的文本，每作用域上限为 `maxInputBytes`；每次运行提取自上次以来累积了文本的每个作用域，并在该作用域自己那一批离开时清空其缓冲——消费即成功，因此失败的调用至多消耗其批次一次，一个坏作用域也不会饿死其它作用域。这些失败不会被吞掉：它们会被收集起来，在巡扫结束后作为一个聚合错误抛出，于是心跳把该次运行记为失败，而不是记成一场丢弃了文本的静默成功。空闲作用域不花任何代价：没有缓冲文本就不解析路由、不发调用。`intervalHours` 并不是全部的门槛：该任务不传自己的空闲阈值，所以还须先经过引擎全局的 `minIdleHours`（默认 2）；而未配置路由的作用域还需要一个能报告路由的存活缓冲会话。若宿主从不空闲那么久，就什么也不会被提取，而其缓冲会持续丢弃最旧的文本。路由在组合给出时取配置的 `provider`/`model`，否则取第一个能报告请求路由的被缓冲会话所用的路由——即 `dsh-evolution-reviewer` 确立的 `resolveTurnRoute` 模式——因此随包提供的 bundle YAML 不需要任何模型值。`profile` 加上拥有该会话的 workspace id 构成作用域，正是评审器、简报注入器与控制器已在使用的同一个 `EvolutionScopeId`。提取在写入任何内容之前校验模型的答案，所用边界与按需的 `extract` 调用相同。

**消费者。** 当 `ctx.get('evolutionGraph')` 有应答时，`dsh-active-memory-context` 在其向量腿之后运行第二条腿。它扫描该轮次自己的前若干个词——至多 `graphLimit` 个——取其中第一个作用域图谱认识的词作为种子，自该种子展开 `graphDepth` 跳，并按每个到达的标签在同一会话语料上各做一次文本搜索。这些命中不带分数，因为它们的相关性是连接而不是距离；渲染器接受它们，并把每一条标注为 `via graph connections`。两条腿由 `fuseSessionRankings` 融合——两条腿都找到的会话排在其一单独找到的会话之前；又因为融合按会话 id 归并，当一个会话有两份文档都达到阈值时，简报只为其保留一行——再由既有的简报渲染器在 `maxBytes` 内输出结果。图谱在同一处守卫内通过 `ctx.get` 读取，因此未挂载、版本较旧、为空或配置错误的作用域图谱会让简报只承载向量腿自己的命中：同样的会话，每个一行，按融合顺序排列。图谱腿仅凭 registry 成员关系解析其作用域，因此只被向量腿通过 canonical-path `cwd` 回退匹配到的会话不会获得图谱腿。`profile`、`graphDepth`（默认 1）与 `graphLimit`（默认 5）都是经过校验的 `Config` 字段，绝不在使用点默认。

没有新的引擎方法，也没有新包：这座桥就是图谱本就发布的标签查找。

## 考虑的替代方案

**边来源——把某条关系读自哪些会话存到边本身上。** 这是精确的连接，但被否决。它需要改动已存记录的形态，并为已存在的图谱做迁移；它会放大写入（一条关系在五个会话中被观察到，就是一条边加五条来源记录）；它还迫使来源列表设定一个别处都不需要的上限策略。查询期标签桥不需要迁移，复用 `find`、`expand`、既有词法通道与既有融合辅助函数；它的模糊性——标签子串匹配而非精确的实体连接——对于一条其命中由融合排序、而非被当作精确答案采信的召回增强腿来说是诚实的。

**一个单独的侧索引域，把实体映射到会话。** 好处相同，但归属不同：一个靠跟图写入与图谱保持同步的第二存储域、一个额外的包，以及一个一致性问题（图后来触及上限或从未写入时，索引行怎么办）。它因为与来源方案相同的理由落败，外加一个新包那么多的失效模式。

**规范中的 `lastExtractAt` 水位线，放在新的 `extract-state` 表中。** 规范把生产者描述为从同一域的一张表读取水位线，并跳过没有新内容的作用域——那意味着域版本提升与迁移，以及一条只有定时器会读的持久记录。消费即成功的缓冲取代了它：文本在内存中累积，提取某作用域的那次运行清空其缓冲，空闲作用域仍然零调用。没有迁移，没有水位线行。代价有界且已记录：若进程在消费这些文本的那次运行之前重启，自上次运行以来观察到的文本会丢失，窗口至多一个 `intervalHours`；缓冲区超过 `maxInputBytes` 时丢弃最旧的消息，而不是拒绝该轮次；而单条消息若大于整个预算则会被整体拒绝而非截断，因此它根本不会被缓冲，也没有任何运行能触及它。

**用整条查询做 `find` 来播种。** `find(scope, query)` 看着无害，实则无效：只有当节点标签包含整个 needle 时才会匹配，因此现实中的多词轮次匹配不到任何标签，这条腿便播不下种子——该功能在正常路径上是死的，而测试靠单词查询却能通过。修正后改为扫描轮次的前若干个 token（受既有的 `graphLimit` 约束，因此没有新字段），并以图谱认识的第一个标签播种。代价是：最早被提到的实体胜过连接最多的实体；若某轮次唯一认识的实体出现在前 `graphLimit` 个 token 之后，则会被漏掉。

**把 `'llm'` 加入服务的静态 inject。** 已否决：图谱的核心是存储加查询，部署完全可以在没有模型的情况下挂载它。通过 `ctx.get` 加守卫获取 `llm` 可以保持 `static inject = ['storageDomain']`，并沿用早前某个包为完全相同的场景立下的先例。没有模型的挂载不会自动提取——而它本来也没有可用于提取的模型。

**在 session-query 引擎上增加图谱方法，或一个图谱感知的搜索模式。** 那会把两个通道放到同一次调用之后。但不会有调用方：融合发生在拥有该简报的 pre-step 监听器里，而两条腿已经说着同一种命中类型。

## 后果

图谱自己会充实起来。挂载了心跳引擎、workspace registry 与模型的组合，从普通轮次中积累出按作用域划分的图谱，`/graph` 能读回学到的东西；这些都未挂载的组合仍然可以存储、查询与按需提取。pre-step 简报多了一条不花模型调用、也不花嵌入调用的腿——标签查找，外加至多 `graphLimit` 次落在该轮次本就搜索过的语料上的词法搜索——并且两条腿都认同的会话排在其一单独找到的会话之前。

陈旧性是有界且被明说的，而非被隐藏：重启时至多一个心跳间隔的未提取文本处于风险中；某作用域缓冲超过 `maxInputBytes` 后最旧的消息被丢弃；大于整个预算的消息被整体拒绝，因此根本不会被缓冲；只有一条腿桥接到的关系靠标签子串到达，绝不靠实体身份。融合腿还继承了向量腿的开关：两个随包组合都以 `openAt: never` 挂载 `dsh-session-query-sqlite`，因此在启用内容搜索之前，图谱腿除标签查找外贡献不了任何内容。

两个包的公开面增加了经过校验的配置与一个导出常量——图谱上的 `intervalHours` 与 `profile`，外加 `EVOLUTION_GRAPH_EXTRACT_TASK`；注入器上的 `profile`、`graphDepth` 与 `graphLimit`——并且两边的 README 与生成的配置目录现在都描述了它们。

尚未完成、记录在案而非被默许的部分：两次并发巡扫可能重复交付同一个缓冲窗口（只有在心跳运行重叠时可达）；图谱腿省略了向量腿对单会话 workspace 的提前返回；其按标签的搜索不携带取消信号，因此被取消的轮次仍要为已开始的词法工作付出代价。

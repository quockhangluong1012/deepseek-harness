# Agent Note: Structured lesson extraction replaces the squeezed lessons document

Status: implemented

[English](2026-09-14-structured-lesson-extraction.md) | 中文

## Problem

Phase 1 把一个作用域的经验变成了结构化工件，但没有任何东西去移动它们。`@deepseek-ai/dsh-evolution-reviewer` 仍然每个受门控回合提取一份 markdown 文档，并用它替换作用域整个工件数组，因此 `validationCount` 与 `refutationCount` 从不移动，衰退只由 `defaultTtlDays` 驱动，而每个回合的回答都要被整份重写——模型某次回答里漏掉的一条事实就此消失。文档是在事后而非由构造本身来收敛的：模型被要求随意给出标题，随后一个纯函数挤压把回答归约为四个记忆标题并按字节预算裁剪，丢弃了部署已经付过费的文本。

本 Agent Note 回答的问题是：什么协议取代了那条流水线，以及这一替代的每一部分各自付出什么代价。

## Decision

一次提取调用向模型展示作用域中最相关的那 `relevantArtifactLimit` 个工件，从 1 开始编号，与本回合的笔录并列，并期待一个 JSON 决策数组：`confirms`（该下标的工件被支持——`validationCount` 加一）、`contradicts`（它被反驳——`refutationCount` 加一，可选携带更正后的 statement 与 confidence），以及 `new`（列出的工件都未覆盖的一条事实——完整的候选字段，其 `source` 取自提取会话）。空数组是常见且有效的回答。笔录记录了工具调用失败的回合还可以为每个被记录的失败追加一条 `critique`——被违背的期望、失败与更正——这半个回答连同它授权的修订见[自我精炼批评笔记](2026-09-22-self-refine-critique.zh.md)。评审器把每个下标解析回它自己发出的那份列表中的真实工件 id，为每个 `new` 候选合成 `source`，然后调用 `evolution-memory` 的 `applyExtractionDecisions`——后者在写入时读到的记录上按决策顺序折入整批。`rebuild` 对它所选的历史材料运行同一条流水线，而不是对回合缓冲。

### 相关性让成本有界，也让完整性有所让渡

排序是可选 embeddings 的，与存储自身的合并步骤一致：挂载 `ctx.embeddings` 时，回合文本与每个工件的 statement 在一次批调用中一并嵌入并按余弦相似度排序；没有挂载、批调用抛错，或回答中缺少查询向量时，排序降级为最近更新优先。排序永不使提取失败——窗口不够相关只是答案更差，不是丢掉一个回合。

窗口正是让一个回合的成本与作用域记忆增长规模无关的东西：提示词展示 `relevantArtifactLimit` 条 statement（默认 20）而非每个工件，而回答的体量随回合而非随存储变化。

它付出的代价在回合之内是完整性，在回合之外则经由衰退体现。本回合文本未能带进窗口的工件不会被那次调用确认，而确认是唯一刷新工件 `updatedAt` 的东西。因此，依赖一条此后各回合不再讨论的事实——一次只做过一次、再未重提的决策，一条只在某次迁移期间重要的约束——的用户，会眼看它在 `defaultTtlDays` 之后衰退，尽管它仍然为真。这是有意为之的交换：每个回合的成本有界且可预测，换来一份只保留作用域自身对话反复重新推导出来的内容的记忆。逃生通道是存储自身不设 `ttlDays` 的写入路径与反驳下限，而不是提取。

### 提示词里是下标，存储里是 id

模型按展示给它的序数寻址工件，从不按 id。序数发出便宜，也不会被幻觉成对另一条事实的写入：评审器拿它对照自己发出的那份列表解析，因此落在列表之外的下标是畸形决策——被丢弃并告警，批次其余部分照常应用——而任何基于下标的取值都不会跨越持久化边界。工件 id 就是规范化后的 statement 文本，因此把它们放进提示词还会诱使模型去编辑它读到的一个 id，而不是它推导出的一条事实。

### `new` 决策仍要经存储的合并解析

模型的窗口不是存储的全部内容，因此它称作 `new` 的候选仍可能重述一个被窗口排除在外、甚至从未展示给它的工件。整批决策因此不采信模型关于「新」的判断：`applyExtractionDecisions` 复用了 `addArtifact` 那套「先度量、再复核」拆分，在进入写入链之前经可选 embeddings seam 解析每个 `new` 候选的合并目标，并在真正被写入的记录上按 id 重新解析所选工件。在默认的 `keep_both` 下，重述已存事实的候选不会被另存在它旁边，而这正是要点：另一种做法是每个回合都为作用域已持有的事实多堆一个近似重复项，直到经验上限或衰退随机地移除其中一个。

### 每次提取调用只有一条暂存条目

回合的一整批决策暂存为单条 `applyDecisions` 条目，因此在审批时读到的记录上原子地应用——与其他每个暂存记忆操作遵循相同的「写入时解析」规则。批准它的评审者是把该回合的推导作为一个整体收下或退回。代价就在这里：一条显然正确的 `confirms` 无法被单独批准，而把同一回合里的一条 `contradicts` 压下来再想想。这一选择是有意的——整批是对一个回合的一种解读，而逐决策暂存会让每回合的条目数倍增，还允许评审者只应用半份推导，把更正后的 statement 和促使它产生却仍未更正的工件并排留下。已知缺口是明说而非隐藏的：待批列表展示 gist 与决策明细，但不展示其背后的笔录证据，因此人仍然无法掂量一条反驳的来源。

### 超出上限时丢弃整条事实，而不是裁剪它

经验上限可能被批次中任意若干条 statement 的组合突破，因此评审器的重试是移除整条决策而不是截断文本：先丢弃最长的一条 `new` statement，再在没有 `new` 决策可丢时丢弃各条 `contradicts` 的替换 statement，同时保留其计数递增。重试次数以该批 `new` 数加一为界，随后把拒绝向上传播。这取代了早先「裁剪并重试」的做法——后者求解存储能接受的最长 statement 前缀：被裁剪的 statement 读起来像完整事实，却没有任何回合为它论证过，也不会有之后的回合再回访它，因为它看起来已经定论。把过大的 statement 推迟到之后的回合会丢掉同样的信息，只是让存储对这件事保持诚实。

### `rebuild` 折入决策，而不是替换文档

重建过去会从历史再生经验文档并把整份写成整个数组，这既使它成为唯一能移除模型不再相信的事实的路径，也使它成为一条可能只因为模型某次漏写就悄悄丢掉事实的路径。它现在对所选材料运行同一条相关性受限协议，因此与实时回合一样地确认、更正与追加。代价是明确的：提取如今完全没有移除路径。退役一条错误事实是衰退的职责——达到 `refutationFloor` 次反驳，或 ttl 过期——或由人或控制面驱动存储自身的 `removeArtifact`。重建再也无法用一次调用清空作用域的事实，也因此不再需要被信任不去这么做。

### 挤压流水线及其配置已被删除

`squeeze.ts`、`LESSON_HEADINGS`、`extractionSystemPrompt` 里针对文档形状的提示、`frameExtractionInput`、已死的 `clipToBytes` 导出，以及 `squeezeBytes` / `squeezeOrder` 两个配置字段都被删除，而不是标记弃用。协议由构造本身收敛输出——受窗口约束的一列 statement，加上一个逐决策 schema，其中只有 `new` 是长字段——因此事后字节预算已无所可用。那四个标题所强制承载的记忆类别（用途、决策、偏好、参考）作为提示词规则中的指引留存下来：它们在那里引导模型去找什么，而不再规定一种之后还必须被挤压回去的文档形状。同一改动把 `maxOutputTokens` 从 `1024` 提到 `2048`，因为它过去的默认值是按一份短小的固定标题文档定的，而繁忙回合的决策数组随它产生的决策条数扩展。

## Alternatives considered

**保留挤压作为协议旁边的安全网。** 它能约束任何被 schema 放行的回答。已否决，因为两者约束的不是同一件事：协议约束「要求什么」，挤压约束「在模型已经花掉 token 产出之后留下什么」。一张只会删文本的网，算不上一份其失败模式就是回答过长的协议的安全网；诚实的失败是被拒绝的批次，而超上限重试已经通过推迟整条决策处理了它。

**向模型展示作用域持有的每一个工件。** 没有排序步骤、没有 embeddings seam、没有落在任何窗口之外的工件，也就没有「被遗忘的事实」式衰退。已否决，因为它让一个回合的提示词与所需输出随作用域增长：持有数百个工件的作用域会需要一份输入预算与专注度，而单个回合的证据并不值得这些，存储的上限也会从记忆上限变成提示词体量上限。

**让模型按 id 寻址工件。** 少一步解析，而且模型在其他工具里本来就收到 id。已否决，因为幻觉出的 id 在边界上不是可检测的错误：它要么命名另一条事实、悄悄损坏它，要么什么都匹配不到，而这两种情况下的决策看起来与有效决策完全一样。越界的序数则可以对评审器自己发出的那份列表做检查。

**逐决策暂存条目。** 评审者就能批准 `confirms` 而把 `contradicts` 压下来等证据。已否决，因为一批决策是对一个回合的唯一一种解读：拆开它会让某回合的更正脱离产生它的语境落地，对一个每条例目只显示一行的命令面来说让待批条目数倍增，还需要一套存储的单次写入批次正是不想引入的部分失败叙事。

**采信模型的 `new` 判断直接添加候选。** 活动部件更少，而且那毕竟是模型就「是否为新」给出的判断。已否决，因为模型是拿评审器选定的窗口判断新旧的，而不是拿存储判断——于是窗口之外的事实会每回合被复制一次，而相似度度量与「两条 statement 是否同一条事实」的门槛本就归存储所有。

**超上限时截断 statement 而不是推迟它。** 有总比没有好。已否决，因为被截断的 statement 是作为一条完整事实存下的，没有任何标记说明它不完整：它读起来已经定论，提取再不会回访它，也没什么能把它与模型真正想写的完整事实区分开。丢掉那条决策再重试是更小且诚实的损失。

**让 `contradicts` 决策删除该工件。** 模型的证据会被直接付诸行动。已否决，因为删除是存储已经通过 `refutationFloor` 与 ttl 拥有的策略决定：一个回合的分歧应当成为趋向衰退的一个数据点，而不是一次破坏性写入，何况把删除权交给提取会让一次糟糕的回合能够抹掉一条事实，其间没有任何计数拦着。

**让 `rebuild` 保持整份替换。** 它曾是唯一的移除路径，也与文档时代相称。已否决，因为它使重建的安全性取决于模型在单个回答里复现它仍然相信的每一条事实：一次遗漏就永久丢掉一条事实，而且两条提取路径——实时回合与重建——会对同一份记忆有相反的语义。

## Consequences

- `validationCount` 与 `refutationCount` 活了。一个回合的证据会移动它们，一条 `confirms` 会刷新工件的 `updatedAt`，而衰退如今跑在作用域自身对话反复重新推导出来的内容上，而不再只跑在存续时长上。
- 相关性窗口既是成本上限也是完整性上限：一条再无人讨论、却仍然为真的事实会按 `defaultTtlDays` 衰退，而且没有任何读者会被告知它曾被知晓。
- 一次提取调用就是一次写入：盖一次 `lessonsUpdatedAt`，而没有任何改动的批次——空批次，或各条决策都命名了记录已不再持有的工件的批次——一个分族时间戳都不盖，但仍把该次调用的来源记录在 `lastExtraction` 上。
- 一次反驳可以替换工件的 statement，而工件保留所有调用方寻址它所用的 id，因此 id 不再拼出它现持的 statement。`addArtifactTo` 因此同时按 statement 与按 id 解析候选，被更正的事实也不会在下一个回合长出一个双胞胎。
- 暂存批次整体审批。没有办法接受一个回合中的某条决策而拒绝另一条，而待批列表展示的是决策明细，不是其背后的笔录证据。
- 提取没有移除路径。退役一条事实要靠衰退（默认三次反驳，或 ttl 过期）或存储自身的移除操作；一条再无回合提起的错误事实会存活到它的 ttl 过期。
- `squeezeBytes` 与 `squeezeOrder` 不再是可接受的配置字段。仍然命名它们的组合什么也设不上，而部署原来的文档字节预算没有继任者：如今约束一次调用的是窗口与 `maxOutputTokens`。
- `maxOutputTokens` 默认 `2048`。曾为一份短文档把旧值 `1024` 调过的部署，现在每回合约有十条决策的余量；更繁忙的作用域应调高它。
- 重建不再是破坏性操作。它无法清空作用域的记忆，也不再依赖模型的回答是对记忆的完整再生。
- 迁移来的作用域仍保留其粗粒度的 `migration-pending` 工件：协议是把决策折入它读到的工件，而不是精化它们，因此 `SweepResult.refined` 仍为 `0`，目前也还没有任何东西拆分那个工件。

## Testing

`packages/evolution/evolution-memory/tests/decisions.spec.ts` 钉住那个纯折入：`confirms` 只增加计数并刷新时刻，`contradicts` 替换 statement 与 confidence 而保留 id、创建时刻与验证数，命名缺席工件的决策被跳过，`keep_both` 对已存身份什么都不存，以及混合批次按顺序作用于此前各条决策产生的结果。`store.spec.ts` 钉住服务路径与暂存的 `applyDecisions` 操作：直接写入、暂存写入加审批、拒绝后记录不变、上限拒绝，以及没有改动的批次不盖任何分族时间戳。`packages/evolution/evolution-reviewer/tests/protocol.spec.ts` 钉住带下标的组帧、带栅栏与不带栅栏的解析、被拒绝的形状，以及系统提示逐字点名全部三个动作。`relevance.spec.ts` 钉住最近优先排序、无向量的工件排在最后，以及 embeddings 未挂载与抛错两种情况下的最近优先回退。`reviewer.spec.ts` 钉住端到端回合：确认抵达存储的计数、反驳推高反驳数、新事实落地为工件、窗口之外的工件从不被引用、畸形回答只告警而已存工件不受损，以及超上限重试丢弃决策。`packages/evolution/command-evolution/tests/command-evolution.spec.ts` 钉住待批列表为一批暂存决策逐条命名，以及对读不懂的载荷只渲染 gist 行。

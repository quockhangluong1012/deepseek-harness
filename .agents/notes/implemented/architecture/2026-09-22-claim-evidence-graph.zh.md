# Agent Note: 声明承载证据、否证与取代

Status: implemented

[English](2026-09-22-claim-evidence-graph.md) | 中文

## 问题

`specs/evolutionary-harness-v11-deep-research.md` §19 要求把记忆做成声明/证据图，而不是一堆笔记；§20 禁止存放单一置信分，转而要求一种"应随独立证据上升、而不随反复回忆同一段记忆上升"的分解；§53 把这两半分别列为 Memory（"有证据支撑的声明图 + 效用反馈"）与 Knowledge Graph（"声明/证据/否证/取代图"）的升级项。仓库此前只建成了它们的记录一半，而且这个缺口就写在各个包里：

- `evolution-graph` 存放实体与有向关系，而一条关系不过是*某个短语从某段文本中被读到了多少次*：它不携带来源，因此没有什么可被否证。它的 README 把后果记录为当前限制——"被后来的资料否证的边仍保留其计数"。
- `evolution-memory` 已经把每次提取分级为 `confirms`／`contradicts`／`new` 决策，并把它们写成一个工件的 `validationCount`、`refutationCount` 与 `confidence`。因此，一条被同一会话确认十次的事实，看上去与被两个会话确认的事实完全一样，而且没有任何东西把一条事实与支持它的证据、它被观察到的轨迹、它取代的旧事实，或消费它的技能连起来。
- 提取路径止于存储：评审器的决策批次抵达 `evolution-memory` 就停住了，因此没有任何其他持久状态能从"某条声明被确认、被否证或被更正"中派生。
- `evolution-metrics` 以缺少召回命中计数器与结果关联为由，把 `memory-utility` 声明为不可测量。

于是，一个作用域可以无限累积证据，却始终说不出它相信什么、依据谁的话、又针对什么。

## 决策

`@deepseek-ai/dsh-evolution-graph` 在关系之外长出一层声明/证据层，`@deepseek-ai/dsh-evolution-memory` 发布喂养它的决策批次。

1. **声明层位于图谱的按作用域记录之内。** 一条 `Claim` 携带 `supportedBy` 与 `contradictedBy`——每个来源一条证据，各含 `source`、`quality`、`reliability`、`firstAt`、`lastAt`、`count`——外加 `observedIn`、`supersedes`、`derivedFrom`、`usedBy`、`status`/`retiredBy`，以及下文的信念字段。`recordClaims` 是写入面，`claims` 在仍然成立的声明上作答，`claim` 按身份读取单条声明，无论其是否已退役。没有新领域、也没有新包：记录新增了一个 zod 带默认值的 `claims` 数组，因此此前写入的图会原样打开，领域版本仍是 1。
2. **信念是推导出来的，绝不来自外部输入。** `deriveBelief` 存储完整的 §20 分解——`confidence`、`evidenceQuality`、`sourceReliability`、`independentSupport`、`contradictionCount`、`recency`——因此消费者能看到一条声明"为何"被相信，而不只是"有多"被相信。置信度等于最强的支持证据质量乘以最受信任的支持来源，再乘以互相独立的支持来源数上的饱和因子 `n / (n + 1)`，除以 1 加上互相独立的矛盾来源数。饱和意味着后续独立来源的边际贡献递减、且任何单一计数都无法到达 1；除法意味着一次矛盾必定压低它所落到的那条声明。
3. **重复观察无法产生强化。** 证据按来源合并：已在该声明上的来源只更新 `count` 与 `lastAt`，并保留它首次作证时的质量与可靠性。因此 `independentSupport` 统计的是来源、而不是读取次数，这正是 §20 禁止的反馈回路。经验工件的 `validationCount` 保留其文档化含义——后来的提取确认该事实的次数，也就是界面所显示的数值——而信念已与它无关：评审器的提示词只渲染 statement，置信度只读来源。
4. **`supersedes` 使其退役，而不改写它。** 声明的身份就是规范化后的陈述，因此改正后的陈述是第二条声明，其 `supersedes` 指向第一条；被退役的声明保留其证据、其连接与在记录中的位置，读作 `status: 'retired'` 且 `retiredBy` 指向取代它者，并且不再回答任何查询。这正是为声明关闭 README 那条"被否证的边仍保留其计数"限制的机制，同时让该限制对裸关系边依然成立——裸边是频次而非信念。退役在整批断言之后统一施加，因此一个批次恰好列出两条声明的先后顺序，无法决定哪条存活。
5. **生产者是随包提供的评审器路径，而不是命令。** `evolution-memory` 在决策批次已持久化之后发布一个 `evolution/decisions-applied` 事件，携带作用域、来源会话、批次，以及该作用域在写入*之前*的工件。图谱把它折成断言：`new` 候选成为一条声明，由其自身的 `source` 以该证据种类的质量与它声明的置信度支持；`confirms` 增加来自作出该决策的会话的支持；`contradicts` 增加来自该会话的矛盾，而携带替换陈述的那种还会立起一条取代被更正声明的新声明。写入前的工件至关重要：`contradicts` 替换 statement 时保留工件的 `id`，因此只有写入前的陈述才指明了"一次更正所更正的是什么"。寻址到该批次从未持有过的工件的决策不构成任何证据，与存储跳过它的方式完全一致。
6. **没有任何新内容到达模型。** 声明层是对评审器已经付费的决策的纯折叠；它不增加提示词、不增加调用、也不增加会话事件。存储的事件只存在于进程内。
7. **监听者无法让发布它的那次写入失败。** 监听者运行时决策批次已持久化，因此抛出异常的消费者只会被记录并隔离，与 `domain/changed` 的观察者完全一致；图谱自身的折叠（它写入第二个领域）只会记录一条警告，而不会让那次记忆调用失败。

## 考虑的替代方案

**为声明单独建一套存储——新领域，或新包。** 否决：声明是作用域级、体量小，并且与该作用域的实体一起被读取，因此第三份作用域状态的持久副本将需要自己的打开/关闭/上限接线，以及每个同时需要两者的消费者所需的第二条读取路径。图谱的记录本就是该作用域的知识索引，声明属于其中。

**在 `evolution_graph` 中开第二张表，而不是给 `records` 加一个带默认值的字段。** 否决：每次查询都整条读取记录，把声明拆出去会让 `read()` 对同一作用域变成两次读取而毫无收益；带默认值的字段还能让已提交的记录无需提升版本号即可打开。

**在 `evolution-memory` 内部统计来源——让 `validationCount` 统计不同会话数。** 否决：`validationCount` 与 `refutationCount` 是被展示的历史（"后来的提取确认该事实的次数"），而评审器从不把它们给模型看，因此改写一个持久字段与一个界面计数器，会把这个修复放到错误的层。信念按 §20 的要求在信念层计算，存储继续记录历史。

**从 `domain/changed` 派生声明，而不是发布批次事件。** 否决：单看记录无法把一次 `confirms` 归因到作出它的那个会话，因此独立支持——也就是 §20 通篇所谈的那个数字——将无法从领域快照中统计出来。事件携带批次、其会话，以及决策当初所寻址的工件。

**用 `/claims` 命令作为生产者。** 否决：这次改动的要点在于随包提供的评审器无需有人开口就能填充图谱。读取面仍是服务 API，留给下一个渲染它的消费者；靠人手推送声明的命令，正是本仓库已经过多的那种形态。

**就地改写被更正的声明。** 否决：身份就是规范化后的陈述，因此改写一条声明的陈述，会让 `supersedes`、`derivedFrom` 与 `retiredBy` 指向记录已不再表达的陈述。更正是第二条声明，旧的那条退役——与工件存储在更正时保留工件 id 所做的取舍相同。

**把 `recency` 加权进信念。** 否决：仅因时间流逝而降低对某事实的信任，需要一个时钟和一个从未有人标定的半衰期，而在纯折叠里凭空发明一个，会把未经测量的策略烘进每一个被存储的置信度。该字段被记录下来，以便消费者——或将来某个有论据的决定——去给它加权；README 也如此说明。

**从记录中删除已退役的声明。** 否决：消费者必须能看到是什么取代了一条声明，而这正是 `retiredBy` 所回答的。已退役的声明不再回答 `claims`，但仍可按身份读取。

**像图谱的上限拒绝实体那样，在写入时拒绝矛盾。** 否决：矛盾是证据，不是违规。被某个来源否证的声明仍以更低的信念成立，只有取代它的声明才使其退役。

## 后果

- `ctx.evolutionGraph` 获得 `recordClaims`、`claims` 与 `claim`，以及 `maxClaims` 上限（默认 `500`，像 `maxNodes` 与 `maxEdges` 一样在写入时生效，且仍允许更新作用域已持有的声明）。在此改动之前写入的图记录会以零条声明打开。
- 填充声明层不消耗模型调用：把图谱与 `evolution-memory` 一起挂载的宿主，会从评审器既有的批次中获得声明，而存储的决策路径在其他方面不变。
- 消费者通过 `contradictionCount` 与 `contradictedBy`、以及它们所除出的置信度，区分一条受支持的声明与一条被否证的声明；被取代的那条读作 `status: 'retired'`，`retiredBy` 指向其继任者，它不在 `claims` 中，但仍可按身份读取。
- 声明写入失败只会被记录，而不会被抛出：它所派生的经验已经存好，而声明是派生状态，丢掉的代价是一次折叠而不是一个事实。
- 图谱仍不发布 invariant 伴生包，新事件只存在于进程内：它不会到达任何模型提示词。
- 包 README 记录了声明层自身的限制：信念是排序而非概率，且 `recency` 不加权；只有评审器的决策会被折叠（手工写入、在界面里修补过、或被衰减剪除的工件都不改动声明）；被存储合并进同义表述的候选仍声明自己的陈述；`supersedes` 指向尚不存在的声明时不会退役任何东西；`usedBy` 可以表达，但在本仓库中没有写入方；上限是拒绝而非淘汰。

## 测试

`packages/evolution/evolution-graph/tests/graph.spec.ts` 新增一个在真实存储之上运行的 `claim graph` 区块。它钉住：两个彼此独立的支持会抬高信念，而重复读取同一个来源——即使重新评级——只改变其 `count`；一个矛盾来源矛盾两次仍只算一次矛盾，而第二个来源会再次除低信念；无论批次把两条声明按何种顺序列出，`supersedes` 都会使其目标退役；自我取代与未知目标都不做任何事，重复取代保留第一位取代者；空白陈述与空来源被丢弃；`maxClaims` 上限拒绝新陈述，但仍更新已持有的声明，且什么都没存下的批次不触发任何写入；查询按信念由高到低返回仍成立的声明并遵守 `maxQueryLimit`，同时已退役的声明不回答任何查询、却仍可按身份读取。

生产者以一体的方式被端到端钉住：把 `evolution-memory` 与图谱挂载在同一个内存后端之上——`new` 候选以其来源、种类质量与声明的置信度创建声明；同一会话的确认只抬高 `count` 而不抬高 `independentSupport`；第二个会话的确认同时抬高两者；不带替换陈述的 `contradicts` 压低其地位；带替换陈述的 `contradicts` 使被更正的声明退役，并立起以作出更正的那个会话为支持的新声明；寻址到批次从未持有过的工件的决策不构成证据；折叠期间领域被关闭只会记录一条警告，而不会失败。

`packages/evolution/evolution-memory/tests/decisions-applied.spec.ts` 钉住事件契约：批次与其写入前的工件在写入之后发布，且携带的是写入前那一刻的工件；没有来源就应用的批次不发布任何内容；经暂存的 `applyDecisions` 审批以该条目的来源会话发布；抛出异常的监听者无法让持久写入失败。

两套测试在 `vitest run packages/evolution/evolution-graph packages/evolution/evolution-memory` 下全部通过（204 个测试、9 个文件），两个包的所有 `src/` 文件都满足按文件 100% 的覆盖率门槛。

## 未触碰之处

关系保留其计数：裸边是频次，声明层完全没有改动 `observe`、`answer`、`expand` 或 `find`。工件计数器保留其文档化含义。`evolution-metrics` 的 `memory-utility` 仍不可测量——`usedBy` 是声明层能够表达的那条连接（哪项技能或策略在消费某条声明），但还没有任何存储把一次召回与一个结果配对，那项测量属于 metrics 包。`/graph` 命令、图谱的提取巡扫、评审器的提示词、`evolution-dreaming` 的晋级门，以及控制器的 wire 面都未被触碰。

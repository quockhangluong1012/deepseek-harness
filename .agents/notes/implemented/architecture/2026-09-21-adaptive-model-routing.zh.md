# Agent Note：自适应模型路由

状态：已实现

[English](2026-09-21-adaptive-model-routing.md) | 中文

## 问题

`specs/evolutionary-harness-v11-deep-research.md` §51 将「自适应模型路由」列为 P1 #20，§28 给出拓扑：任务执行、反思、候选生成、评估与最终晋升审查，每个角色都值得使用不同的模型——AlphaEvolve 的启示正是为不同角色组合更快/更广与更强/更深的模型。Harness 此前每个优化器只有一条配置路由（provider/model 配置）与一个客户端模型选择目录，但没有持久记录：每个进化角色用过哪条路由、各路由测得如何、某角色应当优先使用哪条路由。

## 决策

新增一个包 `dsh-evolution-model-routes`，持有带证据的按角色路由：

1. **角色拓扑即规范的。** `EvolutionRole` 是 §28 列表的有序集合：task-execution、reflection、candidate-generation、evaluation、promotion-review。每个角色各自拥有指派集与证据。
2. **证据来自真实运行。** 优化器在暂存之后立即通过可选存储缝记录每次候选生成的路由及其胜者三元组（与 population、evaluator-health 记录器相同的可选挂载模式）。记录失败只记一条警告，绝不让优化失败。
3. **固定指派胜过证据；证据跟随其后。** `pin` 记录运维者的显式指派；`observe` 以 `observed` 身份 upsert 路由，但绝不降级固定指派。`recommend` 在存在固定指派时返回最新的固定指派，否则在已测度路由中挑通过率最高、平均 token 最少者；两者皆无时返回空。
4. **一个持久域，一个命令面。** `evolution_model_routes` 域（v1）持有 `routes`（以角色+路由为键）、`evidence`（以结果 id 为键），以及 §53 的职责分离所读取的 `duties` 表（以运行+角色为键，见 `2026-09-22-separation-of-duties.md`）。`/routes` 列出各角色指派及其推荐路由、固定一条路由，或读取最新证据。本包挂载进 web-app profile（只写自己的域，不触及任何模型提示词）。

## 备选方案

- 把优化器的单一 provider/model 配置扩成按角色映射——否决：配置会把规范想要学习并持久保存的路由表硬编码，且优化器已有交给存储的治理交接，而不是自行长成一个路由策略。
- 复用客户端模型选择目录——否决：它是面向智能体入口、由 settings 支撑的默认值，不是按进化角色键控的持久证据存储。
- 让 `recommend` 直接改优化器的路由——否决：强制仍是手工运维固定（§58.12 的只记录不强制立场）；优化器保持其配置路由为准，只上报实际使用的路由。

## 后果

- 路由选择现在有证据支撑且可检查：`/routes` 显示哪条候选生成路由测得最好，运维者可把任何角色固定到任意 provider/model。
- §28 拓扑成为持久词汇：消费者可把其余角色（评估、反思、晋升审查）陆续观测进同一存储。
- 优化器保持解耦：记录可选且失败隔离。

## 与计划的偏差

除常规外没有。`RouteSummary` 携带自己的 `role` 字段，让拓扑排序与推荐过滤始终按角色进行；纯函数 `bestRoute` 有意去掉 last-at 平局比较，因为证据行总带最新时刻；`mergeEvidence` 对未测度路由按零报告，不保留死回退分支。

## 测试

路由辅助函数：键分隔、按角色证据聚合（通过率/平均 token/最新时刻）、异角色隔离、provider/model 排序、未测度按零、按最新固定指派再按通过率再按更少平均 token 的推荐、未测度与空角色排除、拓扑顺序。存储：带证据与自动 observed 行的 observe、后续 observe 保留固定身份、固定新建与翻转、按拓扑序的按角色摘要且副本脱离、带角色/路由过滤与最新在前平局的证据列表、固定-然后证据-然后空的推荐、经 zod 规范的重启持久化、启动前读取。优化器钩子：已挂载存储记录路由与结果、未挂载时暂存不变、失败存储记录警告。`/routes`：未挂载、跨 pin/evidence 角色的语法用法、带推荐的指派列出、含存储错误传播的固定、带与不带角色过滤的证据列出、注册与销毁。17 个模型路由测试、3 个新优化器测试、4 个新命令测试通过；新包语句/分支/函数/行 100%，优化器保持 100%。

## 顺带不动

推荐是建议性的：今天只有优化器的候选生成角色记录证据，为其余角色强制执行推荐路由是接下来的适配工作（包内 Known Limitations 有说明）。路由是宿主全局而非按作用域键控；按作用域键控推迟。本包不触碰客户端模型选择目录，后者继续服务于智能体入口。

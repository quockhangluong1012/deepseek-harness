# Agent Note: 实验台账与重复比较式晋级

Status: implemented

[English](2026-09-16-experiment-ledger-and-confidence.md) | 中文

## Problem

`specs/evolutionary-harness-v11-deep-research.md` §29 要求每个实验本身成为可检索的记忆，§47 要求晋级依据不止一次好运，§48 要求一次运行记录下足以与随机运气区分开的信息。对 §51 的普查发现三者全部缺失：`EvolutionOptimizer.optimize` 在运行之间不保留任何东西，因此同一个失败的改写可以被反复产出又反复丢弃，后续运行看不到哪些算子或场景已经试过，而一次对重评基线的比较就是晋级的全部证据。

## Decision

两个机制，都在 `dsh-evolution-optimizer` 内，因为它们是同一次运行的写入侧与读取侧：

1. **凡走到评估阶段的运行都留下一行持久记录。** 优化器打开自己的存储域（`evolution_experiments`，`src/experiments.ts`），并在每次变异产出候选正文的运行之后追加一行：身份与时间、作用域、技能、证据文本、产出候选的变异算子、搜索与 holdout 场景、基线与优胜者三元组、置信度计数、结果、原因、创建分选条目时的 staged id、provider 与模型，以及运行起始正文与被晋级正文的 SHA-256。正文本身不存储——由摘要标识。`experiments(scopeId, { skill, limit })` 按最新优先返回，`/curator experiments [skill]` 打印它们，每个作用域保留 `maxExperiments` 行，新行落地时丢弃最旧的。
2. **已批准的晋级构成下限。** `regressionFloor` 读取该作用域已决的分选条目，保留该技能**已获批准**的那些，并查出在同一「可比性键」下测量出的最强记录优胜者——该键包含搜索场景（与顺序无关）、provider、模型，以及每个场景的尝试次数。被批准结果支配的优胜者会被拒绝，返回 `status: 'regressed'`，在报告中点名该下限（`floor: { triple, stagedId, at }`），且不分选任何内容。该键之所以存在，是因为来自另一批场景或另一次尝试次数的三元组描述的是另一种测量；现在每一行都记录 `samples`（已评分场景中最少的尝试次数），以便该键能包含它。
3. **`confirmationRuns` 把一次胜利变成可重复的胜利。** 在搜索、holdout 检查与 Pareto 选中之后，每一轮额外运行都在全新进程下把基线与优胜者作为一对再评一次；晋级要求优胜者赢下每一对。输掉一对的优胜者会被拒绝，返回 `status: 'unconfirmed'` 与 `confidence: { runs, wins }`，这些成对比较与搜索共用同一套预算上限。

`OptimizeReport` 新增 `confidence` 与 `floor`，`status` 新增 `unconfirmed` 与 `regressed`，`optimize` 变成一层薄包装：记录 `execute` 的返回值——从未产出候选正文的运行（无遥测记录、低于触发门、正文不可读、变异答案为空）不写入任何内容。

## Alternatives considered

- **写进 `evolution-memory` 的作用域记录。** 否决：那条记录是模型可见内容——它被渲染进简报并参与提示摘要——而且有字节上限。实验历史面向运维且无界，写进去会挤占记忆内容并改变每一份简报摘要。
- **复用整理器的台账。** 否决：那份台账是另一服务拥有的、按内容寻址的补丁历史，优化器并不是它的写入方；共用会为一条读取路径耦合两套生命周期。
- **重新采样场景、种子或模型路由的确认方式**（规范里的「多种子、多任务切片、不同评审路由」）。延后而非否决：它需要比调用方场景列表更大的语料与每轮清单数据；本次改动记录了双方正文的摘要，以便后续重复可被识别为可比。先重复同一对是诚实的第一步——它排除的是「一次比较的幸运读数」，不是「一份幸运语料」。
- **用置信区间而非「全胜」来把关晋级。** 暂时否决：评分器的三元组是每个场景三次尝试取中位数，在其上编造区间会宣称比 harness 实际测量的更强的统计力。
- **比较所有已记录的优胜者，而不只是已获批准的那些。** 否决：尚未被裁决、或已被人类拒绝的分选条目不构成「已被接受的改进」，把它当下限会挡住正是用来修正它的那次改动。
- **把下限放进它自己的持久记录。** 否决：台账已经存了优胜三元组、场景、路由与尝试次数，`evolution-memory` 已经存了裁决；第三份副本可能与其中任何一份不一致。
- **台账写入失败时让整次运行失败。** 否决：晋级已经在记忆存储中发生，因为一行诊断没落盘就把一次成功的分选变成错误，会让调用方失去它唯一的抓手。失败改为在 host logger 上报告。

## Consequences

第二次运行现在从第一次测量过的东西出发，晋级需要它的比较可重复，每个算子、场景集与被留出的失败事后都可读。代价写在包 README 中：台账记录的是运行而不是批准（统计被接受的改进需要同时读作用域的分选条目决议）、确认重复的是比较而不是语料、大于 1 的 `confirmationRuns` 会把一次运行的评分成本乘以该计数。

下限的一个公开假设写在包 README 中：它只把候选与在同一条件下测得的结果相比，也只防守人类接受过的晋级。当没有任何已批准晋级共享该键时 `floor` 为 null，这也是任何人在尚未批准任何东西前看到的状态。

验证：68 个优化器测试（台账写入、按结果的各行、触发跳过不写入任何内容、按技能与作用域过滤、分页上限、保留策略、确认的胜与负路径、确认阶段的跳过、确认期间花完预算、回归下限的拒绝与放行、被拒绝的晋级/异场景集/不同尝试次数各自取消下限，以及仍然返回晋级的损坏台账）加上 `experimentPage` 与 `staleExperiments` 的纯测试，以及 111 个命令测试（含新子命令的空、过滤与未过滤列表）。`packages/evolution/evolution-optimizer/src` 的语句、分支、函数与行覆盖率均为 100%。

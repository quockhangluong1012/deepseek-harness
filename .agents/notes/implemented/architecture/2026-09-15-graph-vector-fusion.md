# Agent Note: The knowledge graph gains a producer, and a seat in the pre-step brief

Status: implemented

English | [中文](2026-09-15-graph-vector-fusion.zh.md)

## Problem

Specification §17 asks for vector search (discover) fused with graph search (navigate). The repository owned every part except two.

`dsh-evolution-graph` had a store and a query API — `observe`, `answer`, `expand`, `find`, read through `/graph` — but no production producer: nothing ever called `observe` outside tests, so every graph was empty forever. And the graph held no session provenance, so an entity reached by traversal could not be joined to a session hit without inventing a link the schema does not carry.

`dsh-active-memory-context` searched past sessions by similarity alone. A session attached to an entity the user just named never surfaced unless its text also resembled the turn — proximity and connection are different relations, and only one of them was being asked.

Three constraints came from the repository rather than the specification. `packages/AGENTS.md` requires optional services to be acquired through `ctx.get(name)`; a storage-only deployment must keep loading the graph even with no model mounted. The repository's own fusion helper (`fuseSessionRankings`) already defines reciprocal-rank fusion over session hits, so the merge rule had to be reused rather than re-derived. And every seam is reached structurally — a local interface plus a `Reflect.get` guard — so neither package takes a dependency on the other's package, only on the shape it publishes.

## Decision

Two halves joined by a label bridge.

**The producer.** Mounted beside `dsh-evolution-heartbeat`, `dsh-evolution-graph` registers the task `evolution-graph-extract` at `intervalHours` (default 6). It buffers the text of each scope's user and assistant messages as they are published, capped at `maxInputBytes` per scope, and each run extracts every scope that accumulated text since the last one, clearing each scope's buffer as its own batch leaves — consume-on-success, so a failed call spends its batch at most once and one bad scope cannot starve the others. The failures are not swallowed: they are collected and rethrown as one aggregated error after the sweep, so the heartbeat records the run as failed instead of a silent success that discarded the text. An idle scope costs nothing: no text buffered means no route resolved and no call made. `intervalHours` is not the whole gate: the task passes no idle threshold of its own, so the engine's host-wide `minIdleHours` (default 2) must also have elapsed, and a scope with no configured route needs a live buffered session that can report one. A host that never idles that long extracts nothing while its buffers keep dropping their oldest text. The route is the configured `provider`/`model` pair when the composition names one, otherwise the request route of the first buffered session that can report one — the `resolveTurnRoute` pattern `dsh-evolution-reviewer` established — so the shipped bundle YAML needs no model values. `profile` plus the owning workspace's id forms the scope, the same `EvolutionScopeId` the reviewer, the brief injector, and the controller already use. Extraction validates the model's answer before anything is stored, at the same boundary the on-demand `extract` call uses.

**The consumer.** When `ctx.get('evolutionGraph')` answers, `dsh-active-memory-context` runs a second leg after its vector leg. It scans the turn's own leading words — at most `graphLimit` of them — takes the first the scope's graph knows as a seed, expands `graphDepth` hops from it, and searches the same session corpus by text once per reached label. Those hits come back unscored, because their relevance is a connection rather than a distance; the renderer accepts them and marks each `via graph connections`. The two legs fuse by `fuseSessionRankings` — a session both legs found outranks one only a single leg found, and since fusion keys by session id the brief carries one line per session where two documents of one session both qualified. The graph is read through `ctx.get` inside one guard, so an unmounted, older, empty, or misconfigured graph leaves the brief to the vector leg's own hits: the same sessions, one line each, in fusion order. The graph leg resolves its scope from registry membership alone, so a session matched only by the vector leg's canonical-path `cwd` fallback gains no graph leg. `profile`, `graphDepth` (default 1), and `graphLimit` (default 5) are validated `Config` fields, never defaults at the point of use.

There is no new engine method and no new package: the bridge is the label lookup the graph already published.

## Alternatives considered

**Edge provenance — storing the sessions a relation was read from on the edge itself.** This is the precise join, and it was rejected. It needs a stored-record shape change and a migration for graphs that already exist, it multiplies writes (one relation observed in five sessions is one edge and five provenance entries), and it forces a cap policy for the provenance list that nothing else needs. The query-time label bridge needs no migration, reuses `find`, `expand`, the existing lexical channel, and the existing fusion helper, and its fuzziness — label-substring matching rather than an exact entity join — is honest for a recall-enrichment leg whose hits are ranked by fusion, not trusted as a precise answer.

**A separate side-index domain mapping entity to sessions.** Same benefit, different owner: a second storage domain kept in sync with the graph by follow-the-graph writes, an extra package, and a consistency question (what happens to index rows whose graph was later capped or never written). It loses for the same reason as provenance, plus a new package's worth of failure modes.

**The specification's `lastExtractAt` watermark in a new `extract-state` table.** The spec describes the producer as reading a watermark from a table in the same domain and skipping scopes with nothing new — which is a domain version bump and a migration, and a durable record whose only reader is a timer. The consume-on-success buffer replaces it: text accumulates in memory, the run that extracts a scope empties its buffer, and an idle scope still costs zero calls. No migration, no watermark row. The price is bounded and documented: text observed since the last run is lost if the process restarts before the run that would have spent it, a window of at most one `intervalHours`; a buffer past `maxInputBytes` drops its oldest message rather than refusing the turn; and one message larger than the whole budget is refused rather than clipped, so it is never buffered and no run can reach it.

**Seeding from a whole-query `find`.** `find(scope, query)` looks inert and is: a node matches only when its label contains the entire needle, so a realistic multi-word turn matched no label and the leg seeded nothing — the feature was dead on the normal path while the tests passed on single-token queries. The correction scans the turn's leading tokens (bounded by the already-existing `graphLimit`, so no new field) and seeds from the first label the graph knows. The trade is that the earliest-mentioned entity wins over the most-connected one; a turn whose only known entity is mentioned past the first `graphLimit` tokens is missed.

**Adding `'llm'` to the service's static inject.** Rejected: the graph's core is a store and a query, and a deployment can mount it with no model at all. Acquiring `llm` through `ctx.get` with a guard keeps `static inject = ['storageDomain']` and follows the precedent an earlier package set for exactly this case. A mount with no model extracts nothing automatically — and has no model to extract with.

**A graph method on the session-query engine, or a graph-aware search mode.** It would have put both channels behind one call. No caller would exist: the fusion happens in the pre-step listener that owns the brief, and the two legs already speak the same hit type.

## Consequences

A composition that mounts the heartbeat engine, the workspace registry, and a model accumulates a per-scope graph from ordinary turns, and `/graph` reads back what was learned; a composition that mounts none of them still stores, queries, and extracts on demand. The pre-step brief gains a second leg that costs no model call and no embedding — label lookups plus at most `graphLimit` lexical searches over the corpus the turn already searched — and a session both legs agree on outranks one only one leg found.

The staleness is bounded and stated rather than hidden: one heartbeat interval of unextracted text at risk on restart, the oldest message dropped once a scope's buffer exceeds `maxInputBytes`, a message larger than the whole budget refused outright and so never buffered at all, and a relation that only one leg bridges reached by label substring, never by entity identity. The fused leg also inherits the vector leg's opt-in: both shipped compositions mount `dsh-session-query-sqlite` with `openAt: never`, so content search must be enabled before the graph leg can contribute anything but label lookups.

Each package's public surface grew by validated config and one exported constant — `intervalHours` and `profile` plus `EVOLUTION_GRAPH_EXTRACT_TASK` on the graph, `profile`, `graphDepth`, and `graphLimit` on the injector — and both READMEs and the generated configuration catalog now describe them.

Left undone, recorded rather than implied: two concurrent sweeps can double-deliver the same buffer window (reachable only if heartbeat runs overlap), the graph leg omits the vector leg's early return for a single-session workspace, and its per-label searches carry no cancellation signal, so a cancelled turn still pays for the lexical work it started.

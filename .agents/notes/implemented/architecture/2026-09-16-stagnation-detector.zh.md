# Agent Note: 停滞检测器

Status: implemented

[English](2026-09-16-stagnation-detector.md) | 中文

## Problem

`specs/evolutionary-harness-v11-deep-research.md` §32 描述了一种「静默的进化死亡」：一代又一代运行什么都没晋级，每一次都在重复那套早已失败的搜索，而从外面谁也看不出来。优化器手里其实握着察觉它所需的一切——[实验台账](2026-09-16-experiment-ledger-and-confidence.zh.md)记录了每次运行的结果与产出候选的算子——却没有任何读者。因此，`operators` 阵容固定的技能会永远在同一失败模式上重跑同一个算子，一次运行一次 `no-improvement`；而读 `/curator optimize` 的人也无法分辨这是第一次尝试还是第二十次。

## Decision

**最近若干次已评估运行全都没有晋级的技能被报告为停滞，同时本次运行切换它抽取候选所用的算子。**

- `mutationStrategy(request)` 读取该技能最新的 `stagnationWindow` 行台账（默认 5），保留其中走到评估的那些；当窗口已满且其中没有任何一行结果为 `staged` 时，判定该技能停滞。从未评过基线的运行不记录结果，因此它既不会填满窗口，也不会清空它。
- 对停滞的技能，本次运行只从配置里那些在该窗口内没有产出候选的算子中抽取候选——那是一套尚未在这个失败模式上失败过的阵容。当配置里的每个算子都已在该窗口内产出过候选，组合内部的多样性就已耗尽，于是沿用配置阵容。阵容不会超出 `operators` 去扩充：本机制无权发明一个部署没有配置的算子作为多样性来源。
- 本次运行抽取候选所用的阵容现在是被记录的事实（每行的 `portfolio`），与 `operators` 区分开来——后者仍是「产出过候选的算子」。后续运行与人类读者因此能分清搜索**计划**了什么、以及**得到**了什么。
- `OptimizeReport` 新增 `stagnant`，`/curator optimize` 在成功行里说明它，`/curator experiments` 打印每行的算子——台账的读者现在既能看到这一切换的原因，也能看到它本身。

## Independence from the repeat guard

停滞运行的阵容与「台账本会据此拒绝它」的那次运行的阵容不同，因此实验键不同，新阵容照常运行。两个机制读同一批行、作用于不同的行：闸门读的是假说，检测器读的是结果。

## Alternatives considered

- **从分数三元组判断停滞**（N 次运行内通过率或 token 无改善）而不是从结果字段判断。否决：台账的结果字段已经编码了这些三元组所经历的比较，包括 holdout 拒绝与批准下限；从原始三元组重新推导，等于在第二处复制这份判断，还得为它另行争论一套容差。
- **把停滞计数放进它自己的持久记录。** 否决：证据就是同一批台账行，而计数器必须与保留策略同步——保留会在新行落地时丢行。
- **越过配置去扩充阵容**（把内置算子各跑一遍）。否决：`operators` 是部署的成本决策——每个算子都是一次独立的模型调用——一个能推翻它的机制会花掉运维没批准的钱。
- **通过更换模型路由来反应**（规范里更靠后的阶梯：新任务、新评审、新模型）。延后而非否决：路由是插件配置，运行本身无法另选一个，除非存在尚不存在的路由 seam。本次改动执行代码能自行完成的第一级——更多多样性——并报告那些足以支撑后续阶梯的状态。
- **只按连续 `no-improvement` 次数设阈值。** 否决：`unconfirmed`、`holdout-rejected` 与 `regressed` 同样证明当前打法行不通；只统计一种结果，会在什么都没晋级的情况下把状态报成健康。
- **停滞期间干脆拒绝运行。** 否决：规范对停滞的回应是换策略而不是停摆，而停摆需要有人注意到一份没人读的报告。

## Consequences

进化死亡现在在报告里与命令行上都可见，停滞的技能会在其配置组合内换个地方搜索，而不是重复自己。代价写在包 README 中：这一切换不是治愈——它改变的是从哪些算子抽取候选，而不是场景、模型或算子集合——而且在单算子组合上它是不可见的：窗口里唯一的算子同时也是唯一的替代品。

验证：79 个优化器测试，包括停滞运行只从「什么都没产出」的算子抽取候选而健康运行使用完整阵容、组合耗尽时沿用配置阵容，以及从未评估的运行既不被重复闸门记住也不计作停滞。`packages/evolution/evolution-optimizer/src` 的语句、分支、函数与行覆盖率均为 100%；111 个命令测试，包括优化报告上的停滞后缀与实验台账中的算子列。

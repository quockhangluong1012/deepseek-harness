# Agent Note: 经验工件取代经验文档

Status: implemented

[English](2026-09-13-lesson-artifact-model.md) | 中文

## 问题

演进式 Harness 规范要求每条长期记忆工件都携带结构化的来源与质量元数据——statement、source、conditions、evidence、confidence、校验与反驳计数、scope、ttl。`@deepseek-ai/dsh-evolution-memory` 把整个 `agentLessons` 存成一个 markdown 字符串，靠子串手术编辑：`addLesson` 在一个 `includes()` 判断之后追加文本，`replaceLesson`/`removeLesson` 定位一个期望恰好出现一次的子串。没有按事实的身份、没有置信度、没有来源，也无法表达“这条事实已被反驳三次”——因此没有任何东西能被衰退、排序或校验，而模型改一句话就得重写一整份文档。

Phase 1 就是把这一层重塑为工件模型。本 Agent Note 回答的是代码本身答不了的问题：在若干都说得通的重塑中，选中的是哪一个，以及每一个选错时的代价。

## 决策

`EvolutionMemoryRecord.agentLessons` 是 `readonly LessonArtifact[]`。工件的身份就是其规范化后的 statement——转小写、空白折叠、首尾去空——该身份即是其 `id`；同一记录内身份两两不同，因此每个操作恰好命名一个工件，且 `updateArtifact` 无法移动它所寻址的那个名字。按身份寻址的操作是 `addArtifact`、`updateArtifact` 与 `removeArtifact`，同名的暂存操作具有相同载荷。

### 只有 `agentLessons` 变成工件集合

`instructions` 保持自由文本，因为它由用户撰写：没有可供打分的推断，没有可校验之物，直接指令上的置信度数字只是噪声。`userProfile` 保持自由文本，因为它是关于一个人的叙述，而不是一组离散事实——拆分它是摘要决策，不是来源决策。工件形状描述的是一条模型推断出的、可能出错且有置信度可打的事实，这恰好就是 `agentLessons`。把改动限定在这里也限定了波及面：画像与指令的写入路径、上限与时间戳都不受影响。

### 接纳采用 `version: 2` 加 `compatibleVersions: [1]`

版本 1 把 `agentLessons` 存为 markdown 字符串。按记录存储的后端会把版本戳不在接受集合（当前版本加声明的 `compatibleVersions`）内的文档读作缺席记录，这是有意为之，好让一个过期文件不会拖垮整个存储单元。因此，单纯升到 `version: 2` 在既有安装上不会大声失败，而是静默地把每个作用域都读成空。记录 schema 继续解析旧字符串形状，`compatibleVersions: [1]` 让旧戳继续可读，于是旧记录能打开，其首次写入盖上版本 2。

### 不采用 `invalidRecords: 'backup-and-skip'`

该策略服务于那些记录是可丢弃派生数据的域：后端把未通过 schema 的记录挪到一旁，打开继续。演进记忆存放的是用户撰写的指令、从会话派生的画像文本，以及无法从日志重建的暂存写入——别处没有第二份副本。此处 schema 失败意味着真实的用户输入会被静默挪走并遗忘，因此本域保留大声的默认行为：打开以 `invalid-record` 拒绝并指明作用域。上面的 `compatibleVersions` 声明正是让这种严格性可存活的原因，因为它覆盖了磁盘上实际存在的所有形状。

### 迁移是同步接纳，随后异步精化

`read()` 按契约是同步的，每个消费者都不加 await 地调用它；而 LLM 拆分不是。因此迁移不可能是读取时惰性迁移，除非把 `read()` 变成异步并重写每一个调用方。取而代之，记录 schema 的 `z.union` 在解析时把旧字符串接纳为一个粗粒度工件——`statement` 即整份文档、`source: 'migration-pending'`、`evidence: 'inference'`、`confidence: 0.5`、`scope: 'project'`、两个计数均为 `0`、无 ttl——而拆分它该由心跳任务完成。代价是：在 Phase 2 落地之前，迁移来的作用域在简报里渲染成一行极长的工件，而不是一组事实。这正是 `SweepResult.refined` 存在且在 Phase 1 恒为 `0` 的原因：这个计数是对尚未完成工作的诚实占位，不是对已完成工作的谎报。

### 合并目标针对正在写入的记录解析

`addArtifact` 通过可选的 `ctx.embeddings` seam 度量相似度，而该 seam 是异步的，表的 `update` 回调却是同步的——因此目标必须在进入写入链之前、依据读到的记录选定。等到写入真正落盘时该快照已经过期：并发调用可能已经编辑或删除了被匹配的工件。因此写入路径会针对正在写入的记录按 id 重新解析所选目标，回退到候选自身的身份，再回退到全新工件，因此一次报告成功的追加永不因另一写入抢跑而丢弃自己的候选。在 `keep_both` 下，身份已存在时不重新解析而是不存储任何内容，因为共享同一身份的两个工件无法区分。

### `replaceArtifacts` 是文档级操作，不是垫片

markdown 提取流水线把作用域的经验重写成一份文档，且尚未发出逐候选操作。若用按身份寻址的操作表达它，就意味着“全删 + 全加”这一对操作：两次写入、两次盖章、一段可观测的中间空态，而且这种“替换”无法区分“模型丢掉了这条事实”与“另一位写入者在中途删掉了它”。一个文档级动词把意图一次说清。它不是旧 `setLessons` 的兼容别名：它把每个候选校验为一个带全新身份、计数与时刻的新工件，并拒绝重复身份的列表，而不是静默保留最后一个。

### 衰退是心跳扫描，不是读取路径上的判断

`sweep` 丢弃被 `refutationFloor` 判定、或自最后一次触达它的写入起 `ttlDays` 已过的工件；且只有在挂载了心跳时，存储才注册 `evolution-memory-maintenance` 来运行它。读取永不剪除：读取是热路径，而剪除是一次写入。需要留意的后果是，保持一个工件存活需要一次触达它的写入——一次精化遍历或一次显式编辑——永不来自读取；而在 Phase 1，还没有任何东西写入校验。

## Alternatives considered

- **保留文档并加一份事实的旁路索引。** 同一批事实的两种表示，只要有一条写入路径更新了其中之一，两者立刻漂移，而且渲染器与提取提示读的仍是那份文档。否决：只留一种权威形状。
- **升到 `version: 2` 但不声明 `compatibleVersions: [1]`。** 差异最小，却会在打开时静默清空每个既有作用域——这个故障模式之所以不可见，恰恰因为后端的契约就是“过期戳读作缺席”。否决；该声明正是把一个数据丢失缺陷变成一个可读记录的东西。
- **在兼容声明之外再加 `invalidRecords: 'backup-and-skip'`。** 它能让将来某条畸形记录失败而不拖垮整个域的打开。否决：它要挪走的记录是用户撰写的指令与没有第二份副本的暂存写入提案；静默丢掉其一比拒绝启动更糟，而且大声失败还能手工恢复，被跳过的记录则不能。
- **读取时惰性迁移并做 LLM 拆分。** 不必调度任何迁移步骤，文档也不会长期处于粗粒度。否决：`read()` 是同步的，每个消费者都按同步对待它，这意味着存储、注入器、评审器、控制器与客户端都要改成异步读取路径——比它所要迁移的那次变更大得多。
- **为每个工件生成与 statement 无关的随机身份。** statement 被编辑时身份保持稳定，且这是持久记录的显然首选。否决：随机 id 让完全重复检查变成扫描比对而非键查找，让暂存操作无法命名一个调用方可计算出的工件，也丢掉了“同一条事实总是键到同一个工件”这一性质。取而代之接受的代价是：编辑 statement 等于一次删除加一次新增。
- **默认合并（`addArtifact` 默认 `merge` 而非 `keep_both`）。** 存储里的近似重复更少。否决：一次错误的相似度判断就会改写一条用户从未要求更改的事实；`keep_both` 只可能新增，因此它最坏的结果是一条可见的重复项。
- **让 `updateArtifact` 也能修补 statement。** 修复只需一个操作而非两个。否决：身份由 statement 派生，一个移动它的 patch 要么让 `id` 变得不对，要么静默地把工件重新键到调用方已经持有的名字之下。
- **在读取时执行衰退。** 无需注册或配置心跳任务。否决：剪除是一次写入，而一次会改状态的读取会让每个消费者的成本模型都不成立。

## Consequences

- 每个工件都携带来源、置信度与计数，将来的提取可以推动这些计数；存储可以对事实排序与剪除，而不是把作用域的经验当作一坨不透明的整体。渲染器已经在花这份收益：简报按强度从强到弱排序工件。
- `maxAgentBytes` 的含义变了。它曾是单个 markdown 文档的上限；现在它是序列化后各工件字节之和的上限，而每个工件都把自己的 statement 携带两次——一次作为 `statement`，一次作为给它命名的规范化 `id`——外面还有固定外壳。按文档调过该值的部署现在要为 JSON 数组做预算，`@deepseek-ai/dsh-evolution-reviewer` 的 `squeezeBytes` 也正是因此改为按新度量记录。
- Phase 1 的计数从不移动：在 Phase 2 之前，没有任何东西写入校验或反驳。在那之前衰退由 `defaultTtlDays` 驱动（经普通写入路径接纳的每个工件都会被赋予一个），这是真实的行为变化而非休眠的机制——没有后续写入触达的工件会在其 ttl 之后被剪除。
- 迁移来的作用域在 Phase 2 之前是粗粒度的：一个工件的 statement 就是整份旧文档，在简报里渲染成一行，并且被任何计数的东西记为一个事实。它是正确且永久的兜底形态，不是损坏状态，而 `refined` 在此期间如实报 `0`。
- 没有挂载 `ctx.embeddings` 时，改写检测关闭：只有规范化后完全相同的 statement 才能匹配，改写过的重复项会另存为一个独立工件。这是能力差异，不是失败——写入永不会因缺少 seam 而拒绝。
- 在已写入版本 2 记录之后回滚代码，会把该作用域读作缺席，因为此前的声明只接受版本戳 1。域是按记录的，文件仍在磁盘上，因此没有任何东西被销毁，但回滚并不保持行为。
- Phase 2（`@deepseek-ai/dsh-evolution-reviewer` 中的结构化提取）仍欠着，而正是它让这套模型活起来：面向作用域当前工件的逐候选 `confirms` / `contradicts` / `new` / `unrelated` 协议，把 `confirms` 接到 `validationCount`、把 `contradicts` 接到 `refutationCount` 与下调的置信度；拆分 `migration-pending` 工件并让 `refined` 成为真实数字的精化遍历；删除 markdown 流水线的 `squeeze.ts` 及其配置；为结构化协议而非短文档设定 `maxOutputTokens` 默认值；以及把 `evolution-controller` 的请求形状改为工件追加协议，而不再是整份文档替换。

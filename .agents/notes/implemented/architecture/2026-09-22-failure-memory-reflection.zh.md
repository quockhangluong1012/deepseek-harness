# Agent Note：失败记忆的反思撰写

Status: implemented

[English](2026-09-22-failure-memory-reflection.md) | 中文

## 问题

`specs/evolutionary-harness-v11-deep-research.md` 的 §4.1 要求建立「失败 → 解释 → 纠正启发式 → 事后检索」这一持续关联，§4.2 固定了一条结构化反思的十二个字段，§4.3 把失败记忆列为 P0 而非可选项，§21 要求显式存储带触发条件与回归用例的「不要这样做」知识。§51 把失败记忆加反模式、以及结构化反思排在 P0 的第 2、3 项。

而仓库此前只建好了记录那一半。`evolution-feedback` 观测失败的工具结果、按会话去重、按工具与消息汇总、给每条汇总判定关键程度，并在 `reflect` 中派生反思的台账那一半。但没有任何东西消费它：

- `recordReflection` 在生产中没有任何调用者——包 README 就明说了这一点——而预定的作者是 dreaming 的 REM 阶段与复审者提炼，两者都没有写。
- 因此 `reflect` 对每个失败都返回为 null 的 `rootCause`、`correctedStrategy`、`reusableWhen`、`antiPattern` 与 `candidateTest`，§4.2 的 schema 始终只有一半有内容，§21 的反模式知识则从未被存储过。
- 也没有任何读路径返回已存反思：反思只能针对调用方自己给出的会话标识组装，没有任何地方把已存反思当作证据读回。
- `evolution-curriculum` 只凭一个差距的失败摘要暂存任务，因此暂存的任务只带一段错误字符串，没有任何纠正启发式。

## 决定

1. **`reflectSignals(limit, now)` 撰写确定性的那一半。** 它按最后写入时间从新到旧遍历存储自身的会话，用既有的 `signals()` 给它们分级，并为每条被判为 `trigger_review` 且尚无反思的信号写入一条反思。已存记录本身就是守卫，因此证据未变时第二趟不写入任何内容；`limit` 限定单趟的上限而不会丢证据——下一趟会把剩下的补上。此处不调用模型：撰写出的那一半只是围绕失败身份及其复发情况的模板。
2. **撰写什么、什么保持为空。** 它写下 `correctedStrategy`（原样重试该调用重现了同一失败——这一复发事实本身就是证据）、`reusableWhen` 与 `antiPattern`（§21 的禁止式陈述连同其触发条件）、以及 `candidateTest`（§21 的回归用例）。`rootCause` 与 `whatWorked` 保持为空，并且在构造上就为空：模板能陈述发生了什么，永远说不出为什么，也看不见尽管失败但已经奏效的部分。`recordReflection` 仍会合并到撰写出的那一半之上而不将其清空，因此分析者依然是唯一的原因陈述者。
3. **`reflections(sessionIds, limit)` 是检索那一半。** 它返回失败曾被给定会话之一报告过的已存反思，按最后写入时间从新到旧排列，并由 `reflect` 使用的同一条代码路径组装——因此读回的反思就是写下的那条反思，而调用方只需要自己既有 seam 已经命名的会话标识。
4. **统一的置信度推导（§20）。** 撰写出的那一半的置信度必须随复发情况变化，而触发复审的信号按定义会让「会话占比」公式饱和（其不同会话数已经达到阈值），因此原先只按会话的公式改为：四分之三取不同会话占比，四分之一取每会话复发占比，两者都相对 `triggerReviewSessions`。独立支持占主导，这正是 §20 关于「置信度应来自独立证据而非反复回忆」的规则；`reflect` 与已存反思报出同一个数值，因为两者由同一个辅助函数组装。
5. **生产消费者是课程。** `propose` 把每个差距匹配到该差距所用会话中最新的一条、其症状属于该差距某条摘要的已存反思，并把该反思的 `antiPattern` 与 `candidateTest` 暂存到提案上，因此课程任务带上的是纠正启发式，而不只是错误字符串。两段文本都是同一条失败结果经空白规范化、各自按自己的预算裁剪后的结果——轨迹摘要按 `maxChars`，反思症状按 `maxMessageChars`——因此身份判定就是前缀包含关系，不需要任何相似度阈值。

## 考虑过的替代方案

- **只针对调用方给出的会话撰写。** 否决：没有调用方持有存储的完整会话列表，而确实持有会话标识的 seam（telemetry、trace）看到的是某个技能运行过的会话，不是失败过的会话。存储拥有自己的观测，因此由它自己遍历。
- **撰写时让模型命名根因。** 否决：这会在按心跳节奏运行的回路里引入模型调用，而写进持久记录的模型根因，在后续趟次把它当作测得事实读取时无从追责。该字段保持为空。
- **在读取时派生反模式与候选测试。** 否决：§21 要求的是存储下来的反面知识，而且正是已存记录让第二趟撰写成为空操作。派生字段还会让写下的反思与读回的反思不一致。
- **把撰写出的置信度存进记录。** 否决：那会让存储的置信度与计算的置信度并存，同一个字段出现两套约定。改为让公式同时覆盖两种写入者。
- **为撰写出的反思新建表或域。** 否决：feedback 域已经有一张以合并键为键的 `reflections` 表，而确定性那一半与分析者那一半的形状完全相同。该域的 schema 与版本都没有改动。
- **按能力或按相似度把课程差距匹配到反思。** 否决：能力是技能、反思是失败，因此能力完全说明不了任务应当复现哪次失败；而摘要与症状是同一条已观察文本的两段裁剪，前缀身份判定是精确的。
- **在 feedback 存储上公开一个会话枚举器。** 否决：回路需要的是它自己 seam 命名的会话的反思，`reflections` 已经回答；枚举器会成为读取同一状态的第二条途径，也会成为把会话集合取错的第二条途径。
- **把启发式追加进课程任务文本。** 否决：任务文本被裁剪到有界预算，因此回归用例会在大多数任务末尾被截掉。启发式改由提案自己的两个字段承载。

## 后果

- 失败记忆首尾闭合：一次在两个会话中被判定的失败，成为一条带策略、触发条件、反模式与回归用例的持久反思，只要域还持有它，就能按会话检索。
- 读取报出的置信度变了。同一会话中出现两次的失败得 0.625（原为 0.75），在两个会话各出现一次的得 0.875（原为 1），不可归因的失败仍为 0.25。所有取值仍在 `[0, 1]` 内，调用方看到的分级顺序不变。
- `evolution_curriculum` 的提案新增两个可空字段，因此域升到版本 2 并声明 `compatibleVersions: [1]`；两个字段默认 null，因此在版本 1 下存储的提案照旧打开。
- 课程提案现在陈述的是它被暂存时当下的那条启发式，而不是读取时重算，因此之后修改撰写模板不会改写已经暂存的提案。
- 此处没有任何内容进入模型提示词。`reflectSignals` 不调用模型，课程也只是把匹配到的东西存下来，而非渲染出去。

## 测试

`packages/evolution/evolution-feedback/tests/reflection.spec.ts` 固定了推导与新的撰写路径。推导测试现在钉住了置信度混合：同一会话内出现两次的失败得 0.625，在两个会话各出现一次的得 0.875，不可归因的得 0.25。两个新测试在两个真实会话中记录同一失败，随后验证：`reflectSignals` 恰好写入一条反思，携带确切的 anti-pattern 与候选测试，且 `rootCause` 与 `whatWorked` 为空；第二趟不写入任何内容；`reflections` 按最后写入时间从新到旧返回已存反思，对从未报告过该失败的会话不报告任何内容；上限限定单趟而不丢证据；分析者的 `recordReflection` 合并到撰写出的那一半之上而不将其清空；两个新读路径在存储启动前都拒绝。

`packages/evolution/evolution-curriculum/tests/curriculum.spec.ts` 在真实会话之上启动真实的失败记忆存储，并从实测差距暂存提案：摘要即反思症状的差距、以及摘要较短且是该症状一段裁剪的差距，两者都带上该反思的 anti-pattern 与候选测试；摘要无关的差距、以及会话从未报告过该失败的差距，两项均为 null；没有失败记忆 seam 的宿主暂存 null；并且启发式是从提案存储读回的，而不只是来自暂存结果。

两个包在其 `src` 每个文件上的覆盖率均为 statements、branches、functions、lines 100%，即本仓库的门槛。

## 保持原样

`recordReflection` 保持其形状与作为分析者路径的角色；生产中仍无人调用它，本次改动也不为它凭空造调用者——确定性撰写者能说出该改成怎么做，但说不出失败为何发生。`summary` 仍只为整理器的观测提示提供计数。feedback 域的 schema 与版本未动。课程的任务文本未改。README 一度列为预定作者的 dreaming REM 阶段与复审者提炼并未在此接线：`reflectSignals` 是课程所消费的确定性作者，模型撰写的原因仍然延期。

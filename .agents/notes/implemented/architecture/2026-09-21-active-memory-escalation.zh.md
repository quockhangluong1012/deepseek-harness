# Agent Note: Active Memory 升级通道（graph-first）

Status: implemented

[English](2026-09-21-active-memory-escalation.md) | 中文

## Problem

`specs/evolutionary-harness-v11-deep-research.md` P1 第 18 项要求 Active Memory 长出升级通道，而不是每轮都跑完整检索。`dsh-active-memory-context` 在每个符合条件的轮次同时运行两条腿——向量腿（每轮一次查询嵌入调用）与图谱腿（本地查找加文本搜索，无嵌入调用）——其 README 原样记录了这份成本且无法避免："每个符合条件的轮次一次嵌入调用"。图谱腿本来就是廉价通道，但没有任何机制能让它先运行、让昂贵通道等待。

## Decision

一个可选的 `Config` 模式，`escalation: 'both' | 'graph-first'`，默认 `'both'`，因此除非部署方要求升级，历史行为完全不变。在 `'graph-first'` 下，pre-step 处理器先运行图谱腿，仅在图谱腿一无所获时才花费向量腿的嵌入调用。未挂载、不适用或结果为空的图谱腿返回空，于是向量腿与之前完全一样地运行，所以升级永远不会丢失纯向量回退：它只在图谱已作答的轮次跳过向量调用。触发条件有意采用命中计数而非相似度阈值——图谱腿的命中是无分数的连接，"至少一个连接"是唯一诚实的闸门，也不引入任何需要部署方校准的可调参数。

## Alternatives considered

- **把默认值反转为 `graph-first`**——否决：跳过向量腿会改变召回形态（只有相似度才能找到的会话会被埋没），而在 shipped 默认里悄悄改变召回是超出本切片的产品行为变更。
- **给图谱腿加相似度式阈值**——否决：图谱命中按设计不带分数，任何阈值都是编造出来的精度；命中计数才是该腿能诚实报告的东西。
- **跨轮次结果缓存**——否决：按设计每轮查询都不同，缓存几乎永远命中不了；README 已记录这一点，而升级打的正是每轮那次嵌入调用。
- **先运行向量腿、在向量命中时跳过图谱腿**——否决：那只省下廉价腿的文本搜索，却每次都花掉嵌入调用，经济学完全反了。

## Consequences

- 挂载了图谱的部署可以用纯相似度召回换取每个图谱已作答轮次少一次嵌入调用，代价写在 README 里而不是藏起来。
- `both` 让既有组合的行为字节级一致；该模式是可在 cordis.yml 修改的校验后 Config，遵循无硬编码可调参数规则。
- 配置目录经 `gen-config-catalog` 在两种语言里都带上新字段。

## Deviations from the plan

- 无：本切片即 §53 升级行落到一个包、一个 Config 字段、一个 pre-step 分支。

- `src/index.ts` 与 `src/render.ts` 语句/分支/函数 100%，由受影响包覆盖率运行的 JSON 报告确认（50 个测试、2 个文件，全部通过）。

# Agent Note：演进记忆的情景层

Status: implemented

[English](2026-09-16-episodic-tier.md) | 中文

## Problem

`specs/evolutionary-harness-spec-v10-complete.md` §2.1 保留三层记忆——情景日志、审定后的语义记忆、版本化的过程技能——并由 dreaming 把情景层固化进语义层。仓库此前只有后两层：语义层（`EvolutionMemoryRecord`：指令、经验工件、用户画像，外加容量与衰减）与过程层（技能注册表 + 整理生命周期）。缺的是情景层：trajectory 导出是面向评测的单会话 ShareGPT 文件，feedback 观察只是失败信号，`/journey` 只是活动历史。没有可供会话追加原始材料的每日日志，dreaming 也只固化 feedback 报告的东西——一条关于「从未失败过的事情」的笔记永远到不了持久记忆。

## Decision

**一个记录字段、一个暂存操作、一条保留规则、一个新增的 light 来源。**

- **情景笔记长在记忆记录上，不另起域。** `EvolutionMemoryRecord.episodic` 是按追加顺序排列的 `{ day, text, addedAt }` 数组，以 `.default([])` 接纳，旧记录照常打开。另起域会把记录已有的作用域隔离、容量核算与版本管理再复制一遍。
- **`appendEpisodic` 是携带 `{ text }` 的记忆类暂存操作。** 审批把笔记原文追加并附上 UTC 自然日，随后剪除：先丢弃超出 `episodicRetentionDays`（默认 7 天）的，再丢弃超出 `maxEpisodicEntries`（默认 100 条）的最旧者。空白笔记会被拒绝，条目留在暂存。该操作不盖任何族——笔记是未经审批的固化输入，不是已审定的文档——但其文本计入容量，且永不进入简报摘要：简报渲染的是已审定的快照，未经审定的原材料不得让一份完全相同的简报重新注入。
- **Dreaming 的 light 阶段把存活的笔记读作候选。** 一条笔记就是一次目击，不同自然日的目击就是 deep 阶段门限所计数的独立语境（`count` 与 `sessions`），因此跨天重复的笔记可以被提升，而只出现一次的笔记只能加强 feedback 同样报告过的失败。复述某条已记录失败的笔记经由既有的陈述同一去重并入该失败的候选，并保留 feedback 候选的 tool。
- **Dreams 记录不记「已消费」。** 笔记在保留窗口内会反复进入 light——deep 阶段的已提升集合本来就会拒绝第二次提升，正如它对待 feedback 反复报告的失败一样。存已消费键会让情景层与 feedback 行为不一致（一次即焚 vs 常驻），除了计数之外没有可观察的效果——而重复的笔记带着衰减后的新鲜度被重新打分，正是对「依然成立」的诚实读法。
- **控制面投射这一层。** `EvolutionMemoryValue.episodic` 把笔记带过 Remote 面，Remote 读者看到的与记录存的三层一致。

## Alternatives considered

- **独立的 `evolution_episodic` 域与服务。** 否决：这一层需要作用域隔离、容量核算与持久版本，而记忆记录全都有；新服务只会为换个表名增加目录、文档与接缝面。
- **绕过暂存写入的直接追加动词。** 否决：暂存路径是已批准方案中的治理——原始模型输出只能经审批进入持久记忆，与其他一切记忆写入遵守同一规则。
- **用不同会话数代替不同自然日数来计数笔记目击。** 否决：笔记不带会话身份，硬造一个会误标字段；门限真正需要的是独立性（跨天稳定的笔记正是 integration 信号所奖励的）。
- **把当日笔记注入模型简报。** 否决：简报是有摘要契约的已审定快照——未经审批的原始笔记会破坏注入器立身所保护的前缀缓存语义；摘要测试已钉住「追加情景笔记不改变摘要」。

## Consequences

作用域在已审定各族之外现在有了一份短命的每日日志，dreaming 同时从原始材料与失败信号中固化——即 §2.1 的情景 → 语义流。代价写在包 README 中：笔记按文本去重（同一意思换措辞的两条笔记算两次目击），只出现一次的笔记在已批准的门限下永远无法自我提升，这一层靠保留期与条数上限约束，而非人工审定。

验证：4 个存储测试（原文追加附 UTC 自然日且不盖族、空白拒绝且条目留暂存、伪时钟下保留期加条数剪除、容量拒绝加摘要稳定）、3 个 `pruneEpisodic` 纯测试、3 个 dreaming 测试（无 feedback 时仅情景成阶段、feedback 与笔记合并只剩一个 `bash` 主题、跨天重复笔记完整 light → deep 提升且采用最早目击的文本），以及控制面投射的情景断言。`packages/evolution/evolution-memory/src` 与 `packages/evolution/evolution-dreaming/src` 的语句、分支、函数、行四项 100%。

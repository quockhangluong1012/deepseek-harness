# Agent Note：停滞检测

状态：已实现

[English](2026-09-21-stagnation-detection.md) | 中文

## 问题

`specs/evolutionary-harness-v11-deep-research.md` §51 将「停滞检测」列为 P2 #23，§32 定义它：检测 N 代无有意义改进，然后自动切换策略——利用 → 多样性 → 新变异算子 → 新任务 → 新评估器 → 新模型——因为一个悄悄停止改进的进化循环就是进化死亡。harness 此前没有任何持久记录表明暂存写入是否持续击败技能最佳成绩，没有"改进以来的运行数"概念，也没有前沿停滞时响应的策略阶梯。

## 决策

新增一个包 `dsh-evolution-stagnation`，持有按技能持久化的运行日志与派生状态：

1. **每次暂存写入都是一次评估运行。** 优化器在 `stageWrite` 之后立即通过可选存储缝记录每次暂存写入：运行 id 即暂存写入 id，代际刻度为该技能运行计数之后的一位，改进标志表明该运行是否在意义上击败技能最佳成绩。记录失败只记一条警告，绝不让优化失败。
2. **有意义的改进要越过下限。** `betterThan` 将一个成绩与最佳比较：第一个成绩总是改进空最佳，通过收益占主导，而在通过不变时，至少 `relativeImprovement` 的 token 减少（或 token 不变时同等规模的耗时减少）才算数；低于下限的均为抖动。`bestOf` 使用同一下限，因此抖动运行永远不会挪动检测器所测量的前沿。
3. **状态在读取时由历史推导。** `status(skill)` 报告最佳成绩、距上次改进以来的运行数、相对配置的 `threshold` 运行数的停滞标志，以及阶梯策略。`strategyFor` 在阈值以下保持常规利用，每满一个阈值跨度攀升一级——`diversity`、`newOperators`、`newTasks`、`newEvaluators`——最终封顶于 `newModel`。配置带默认值校验（`threshold` 5、`relativeImprovement` 0.05），未配置的挂载仍可运行。
4. **一个持久域，一个命令面。** `evolution_stagnation` 域（v1）含一张以运行 id 为键的 `runs` 表。`/stagnation` 汇总每个技能、渲染单个技能的现状与推荐策略、列出运行，并在任务制度变更时重置技能。本包挂载进 web-app profile（只写自己的域，不触及任何模型提示词）。

## 备选方案

- 复用人口存储的代数——否决：人口数的是候选而非评估，检测器的信号是对技能最佳成绩的分数改进，人口存储不做这种比较。
- 从优化器自身的门控推导停滞——否决：门控决定何时优化，而非前沿是否改进；持久运行日志必须跨重启存活并对运维者可见。
- 自动强制策略切换——否决：§58.12 保持信任只记录不强制；检测器只给出下一个策略，更换算子、任务、评估器或模型仍是操作者的职责。

## 后果

- 停滞现在可见且可行动：`/stagnation status writer` 显示最佳成绩、改进以来的运行数与应遵循的确切策略，停滞技能因此不再悄然消耗进化预算。
- 运行日志持久：制度变更时 `reset` 丢弃单个技能的历史；配置变更在读取时重新排序策略，无需重写已记录运行。
- 优化器保持解耦：记录可选且失败隔离。

## 与计划的偏差

除常规外没有。初稿把原始精英顶端当作最佳；那会让低于下限的抖动运行变成"最佳"，使下一个达到下限的收益比较失败。`bestOf` 现在应用与 `betterThan` 相同的下限，因此最佳只在有意义改进时移动。

## 途中修复

初稿让 2% 的 token 下降加上大幅耗时收益在耗时分支下算作有意义；现在耗时分支只在 token 不变时适用，token 收益必须达到下限。测试启动必须向 `ctx.plugin` 显式传 `{}`，因为 Cordis 对带 `static Config` 模式的服务会传 `undefined` 配置。

## 测试

停滞辅助函数：首成绩改进、两种方向的通过主导、token/耗时下限边界、含与不含抖动的最佳跟踪、含重置的改进以来运行计数、含封顶的完整阶梯。存储：自动代数与首运行改进、按下限标记收益、列表排序/过滤/副本脱离、含阶梯策略的状态推导、配置阈值与下限、重置计数、经 zod 规范的重启持久化、启动前读取。优化器钩子：已挂载存储记录暂存胜者、未挂载时暂存不变、失败存储记录警告。`/stagnation`：未挂载、语法用法、状态渲染（停滞与全新）、运行列出、含错误传播的重置、裸汇总。17 个停滞测试、3 个新优化器测试、6 个新命令测试通过；新包语句/分支/函数/行 100%，优化器保持 100%。

## 顺带不动

检测器只记录策略而不执行：更换变异算子、任务、评估器或模型仍是操作者的职责（§58.12，包内 Known Limitations 有说明）。一次运行记录一个测量三元组；配对运行与多种子比较未跟踪。`reset` 是丢弃整个技能历史的粗糙工具；窗口化或衰减历史推迟。

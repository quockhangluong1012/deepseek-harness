# Agent Note：对抗进化

状态：已实现

[English](2026-09-22-adversarial-evolution.md) | 中文

## 问题

`specs/evolutionary-harness-v11-deep-research.md` §45 定义对抗进化——生成器 → 候选 → 对抗者 → 发现弱点 → 修复 → 验证——探针针对八个弱点家族（边缘情形、提示词注入、陈旧记忆、检索陷阱、矛盾证据、工具失败、模糊指令、评估器博弈），§46 增加评估器博弈防御清单，因为只见过友好评估的技能会学会取悦评估器而非在真实使用中存活。harness 此前没有任何持久记录表明一个技能已针对哪些弱点家族做过探针，没有"下一个待探针类别"概念，不跟踪暴露弱点的修复，也没有清单显示哪些博弈防御尚未落实。

## 决策

新增一个包 `dsh-evolution-adversary`，持有按技能持久化的探针日志与派生挑战，外加防御清单：

1. **每条探针都是持久事实，记为未修复。** `probe(input)` 存 `{ probeId, skill, category, probe, foundWeakness, repaired: false, at }`；修复是独立的显式 `setRepaired` 步骤，因此已记录弱点永远不会被悄悄标记为已修复，未知探针 id 会大声抛错。此处不调用任何模型（§58.12）：探针、修复与防御满足都是作为事实记录的操作者判断。
2. **覆盖逻辑是纯函数且零填充。** `categoryCoverage` 按类别统计一个技能的探针数，未探针类别读数为 0；`uncoveredCategories` 按规范顺序列出低于配置 `minProbesPerCategory` 的类别；`nextChallenge` 取第一个未覆盖类别，全部覆盖后则取探针最少的类别并以规范顺序打破并列，使探针轮换而不停止。`weaknessRate` 以发现弱点的探针数除以技能总数，无探针时为 null。
3. **清单跟踪 §46 的六个可自动化防御。** `defenses()` 按规范顺序渲染全部六项，未设置的防御读数为未满足且时刻为 null，因此清单从空存储即可安全渲染；`defenseGaps` 列出开放的防御。人工抽查按设计留在操作者一侧。
4. **一个持久域，只做记录的存储。** `evolution_adversary` 域（v1）含一张以探针标识键控的 `probes` 表和一张以防御键控的 `defenses` 表。挑战在读取时由历史推导，因此下限变更会重新排序下一个类别，而无需重写探针；存储的防御行恒带时刻（`DefenseRow`），而读取模型为从未设置的防御合成开放行（时刻为 null 的 `DefenseStatus`）。

## 备选方案

- 直接从评分器的 `evaluatorDisagreement` 推导挑战——否决：评分器度量每个候选的分歧，而对抗存储记录哪些弱点家族实际被探针过、修复过；分歧是值得探针的分歧来源（README 已链接），不是探针日志本身。
- 复用岛屿的对抗泳道——否决：岛屿目标命名的是进化泳道而非具体提示词；探针日志按技能记录提示词、弱点判定与修复状态。
- 自动强制防御——否决：§58.12 保持信任只记录不强制；清单只列出开放的防御，落实它们仍是操作者的职责。

## 后果

- 对抗覆盖现在可见且可行动：`challenge('writer')` 指名确切的下一个弱点家族，没有任何家族未经测试，已充分探针的技能转入轮换而非停止。
- 修复留有书面记录：每个暴露的弱点在显式 `setRepaired` 之前一直记为未修复，弱点率标出哪些技能需在进一步优化前先修复。
- 博弈清单持久：未设置的防御读数为开放，设置一项永不扰动另一项，操作者一侧的人工抽查按设计留在存储之外。

## 与计划的偏差

除常规外没有。存储的防御行与读取模型拆成两个类型——`DefenseRow`（时刻恒在）与 `DefenseStatus`（从未设置的防御时刻为 null）——因为持久边界校验所存内容，而清单必须能从空存储渲染。

## 途中修复

`z.enum` 需要元组形状的常量，因此两个规范列表沿用 canary 先例（`as const satisfies readonly T[]`）：规范顺序只固定一次，由纯函数与 zod 行共享。最新优先的探针列表以探针 id 升序排定并列，使同一毫秒的批次确定性可解；排序测试对有毫秒间隔的一对按索引断言，对快速尾部按集合断言，绝不断言同一毫秒行的确切顺序。

## 测试

对抗辅助函数：规范顺序固定、零填充覆盖与跨技能隔离、下限一与下限二的未覆盖集合、未覆盖挑战措辞、全覆盖后轮换到探针最少且按规范顺序打破并列、弱点率的 null 与分数、按规范顺序的防御缺口（含缺失行计开放）。存储：探针默认值、修复往返（含显式重开）与未知探针抛错、最新优先列表与过滤及副本脱离、默认与配置下限下的挑战端到端、清单默认值到设置行、经 zod 规范的重启持久化、启动前读取。15 个对抗测试与 8 个存储测试通过；新包语句/分支/函数/行 100%。

## 顺带不动

存储只记录探针而不执行：对技能执行探针并判定弱点仍是操作者的职责（§58.12，包内 Known Limitations 有说明）。一个 `minProbesPerCategory` 适用于所有弱点家族；按类别的下限推迟。人工抽查留在操作者一侧；清单只跟踪六个可自动化的防御。

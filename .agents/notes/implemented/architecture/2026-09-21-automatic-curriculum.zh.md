# Agent Note：基于实测能力差距的自动课程

状态：已实现

[English](2026-09-21-automatic-curriculum.md) | 中文

## 问题

`specs/evolutionary-harness-v11-deep-research.md` §51 将「自动课程」列为 P1 #14（§10、§33）：Harness 应当从实测能力差距中自我提出下一个任务，而不是等用户提供。证据早已存在——压缩学习轨迹（P0 #1）携带每会话的失败摘要，telemetry 把技能映射到加载过它的会话——但没有任何东西从中派生任务，学习因此仍然是被动的。

## 决策

新增一个包 `dsh-evolution-curriculum`，派生并暂存训练任务：

1. **测量是连接，不是模型调用。** `gaps()` 读取已挂载的 telemetry 与 trace seam：对每个带会话的受追踪技能，取其会话压缩轨迹行的去重失败摘要。缺任一个 seam 就什么都测不到。该连接刻意镜像 curator survey 的技能会话→证据连接，使两个消费者看到相同的证据形态。
2. **派生是纯函数且有依据。** `deriveTasks` 为每个带证据的差距派生一个任务，证据最多者优先：任务点名能力、反复失败与会话数，使一次运行可以复现并恢复。任务文本有界（≤240 字符，最多引用 3 条摘要）。
3. **提案持久且去重。** `evolution_curriculum` 域（v1）含一张以提案 id 为键的 `proposals` 表，存放 `{id, capability, task, sourceSessions, gists, at, state}`。暂存会跳过同一 `capability + task` 下的 open 提案；`proposals()` 按 open 在前、最新在前列出；`retire(id)` 刻意退役。
4. **一个命令面。** `/curriculum` 一步完成测量、暂存与列出；`/curriculum retire <id>` 退役一个。本包挂载进 web-app profile（只写自己的域，不触及任何模型提示词）。

## 备选方案

- 用模型生成任务文本——否决：每个差距一次模型调用，对每趟都运行的基座来说不是正确默认；派生文本是诚实的，日后模型作者可在不改变 schema 的情况下叠加。
- 复用 curator survey 输出作为差距来源——否决：curator 是生命周期治理；课程需要轨迹存储的压缩行（作为其 P0 #1 消费者），把两者耦合会模糊归属。
- 仅从能力前沿排序派生任务——否决：前沿按混合证据给技能排序；课程需要失败摘要本身，使任务能够说明要复现什么。

## 后果

- 学习不再被动：每趟都能从实测失败中提出下一个训练/评估任务，直接消费 P0 #1 轨迹基座。
- 任务持久且幂等：重启后仍在，重跑一趟不会为同一差距暂存新任务，退役是显式的。
- 模型可见行为不变：本包不注册提示词、工具或会话事件，也不增加模型调用。

## 与计划的偏差

除常规外没有：差距测量放在服务上（`gaps()`）而不是命令中，使连接只有一个持有者、命令保持纤薄。

## 途中修复

无。

## 测试

派生：无证据的差距不产出任务、按证据广度排序的每差距一条有依据任务、摘要引用封顶、文本裁剪、单会话与多会话措辞。存储：证据下限、对 open 提案去重、open 优先排序、退役路径（未知 id、已退役）、启动前读取。差距测量：两个 seam 齐备（去重摘要、空会话技能跳过）、缺失 seam、无失败摘要的轨迹行。`/curriculum`：未挂载、用法、暂存+列出渲染、未暂存消息、退役成功与失败。12 个课程测试与 139 个命令测试通过；包内语句/分支/函数/行 100%。

## 顺带不动

尚无执行器消费提案——评估/基准与 shadow/canary 工作（P1 #17、#19）拥有运行它们的职责——且提案是宿主全局而非按作用域键控；两者都在包内 Known Limitations 中说明。

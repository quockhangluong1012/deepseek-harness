# Agent Note：带排序信用分配的不可变轨迹总线

状态：已实现

[English](2026-09-21-immutable-trace-bus.md) | 中文

## 问题

`specs/evolutionary-harness-v11-deep-research.md` §51 将「不可变轨迹 + 事件总线」列为 P0 #1：这是学习回路其余部分读取的架构中心（§50）。Harness 其实已拥有原始形态——会话日志是无损、只追加的事件流——`evolution-trajectory` 也把该日志塑造成 ShareGPT 供评测使用，但没有任何东西推导出带逐步信用分配（§3.2）的机器可读学习轨迹或压缩形态（§3.3），因此进化回路没有与决策点绑定的结构化证据。

## 决策

新增一个包 `dsh-evolution-trace`，按需把已提交的会话日志投影为结构化学习轨迹。三个设计承诺：

1. **日志仍是原始轨迹；本包只推导、绝不复制。** `project` 是纯函数：按序号顺序消费已提交的 `SessionEvent` 并构建 `TraceRecord`——turn 携带请求摘要、结局、延迟与 step；step 携带工具调用（调用与结果配对）、来自 `assistant/attempt` 的重试证据、中断标志与 token `usage`；每个 turn 携带失败列表。读取路径先冲刷活动会话。不建存储域、不写、不调用模型：重启后从同一份日志推导出相同记录，且只有一个权威来源。
2. **信用分配是确定性的邻近启发式，明确不是结论。** 对一次失败的工具调用，排序的原因依次是：失败调用本身；同一步骤中早于它的调用（输入生产者）；上一步的调用（上下文生产者）；名称含 `skill` 或 `memory`、可能遗漏了知识的检索调用；最后是 turn 的请求。schema 保持稳定，未来分析者可在不改变消费者的情况下用实测归因替换该排序。
3. **压缩形态按决策排序。** `summarize` 把一条记录归约为学习轨迹行（计数、累计 token/延迟、按首次出现顺序排列的去重失败摘要）；`summary(sessionIds, limit)` 按失败最多 → 重试最多 → token 最多 → 最新排序，使最值得学习的会话在上限之前存活。

一个消费者与本包同时落地：`command-evolution` 中的 `/trace <sessionId>` 为运维人员渲染一个会话的结构化轨迹及其失败原因；本包挂载进 web-app profile（与 trajectory 导出器一样，不写任何东西、不触及任何模型提示词）。

## 备选方案

- 新建存储域保存每会话的轨迹快照——否决：会话日志本身就是不可变原始轨迹；第二份持久化副本会漂移并翻倍存储（「从唯一权威来源派生缓存与查询视图」）。
- 实时观察 `session/event` 并缓冲每会话的 step、增量投影——否决：缓冲复制了日志已有的状态，而按需投影总是与已提交日志一致。
- 在结构化轨迹中保留原始工具参数与完整结果文本——否决：学习形态需要调用身份、结局与摘要；参数与全文由日志保留用于审计。
- 本次同时发出实时的 turn 结清总线事件——否决：没有消费者的事件比没有事件更糟；投影按需读取是当前表面，turn 结清事件随真正需要它的 curriculum 与 shadow/canary 消费者（P1）落地。
- 让 LLM 判定归因——否决：每个失败一次模型调用，对每个会话都经过的基座来说不是正确默认；确定性排序是诚实的，而分析者提供的根因已有 reflection 路径。

## 后果

- Harness 的架构中心已存在：任何消费者都能把任意会话投影为结构化证据，或把多个会话压缩成按决策排序的行，而无需新增存储。
- 失败原因在决策点可得（§3.2）——检索可能遗漏、更早的调用产生了失败输入、请求可能说明不足——因此变异可以瞄准某个组件而非整个系统。
- 模型可见行为不变：本包不注册提示词、工具或会话事件，也不增加模型调用。
- `command-evolution` 新增一个命令；web-app profile 新增一个只读 provider 行。

## 与计划的偏差

- 第一版没有活动事件总线。计划中的「轨迹总线」落实为按需投影加 `/trace` 命令；实时 turn 结清事件推迟到学习系统消费者（P1），使事件不会在无订阅者的情况下发布。
- `command-evolution` 通过 `ctx.get` + 结构类型解析轨迹存储，而不是导入服务类型，与该包中 trajectory 命令的模式一致。

## 途中修复

除常规外没有：删除了 `toTraceTurn` 中未使用的 `maxChars` 参数；去掉了 step 时间推进辅助函数中的死守卫——所有调用点都保证 step 已定义后，该假分支不可达，且会令逐文件 100% 门槛失败。

## 测试

投影：空日志、完整 turn（带空白折叠与非文本块的请求摘要、用量、延迟、结局）、覆盖全部五个等级的排序原因与无上下文的回退、重试、中断、未配对的调用/结果丢弃、重复打开 turn 与 step 的容忍、无关事件忽略、截断及错误码/工具名回退、只在实际上报时保留可选计数的用量求和、最新事件时间戳。压缩：空轨迹无行、计数/token/延迟/摘要去重、开放 turn 的延迟。服务：会话缺失返回 undefined、非缺失的持久化失败重新抛出、活动会话冲刷、按决策优先的 summary 含上限与平局、配置默认值。`/trace` 命令：用法、未挂载、会话缺失、渲染、服务失败、注册与销毁。26 个 trace 测试，包上语句/分支/函数/行 100%；133 个 command-evolution 测试通过。

## 顺带不动

轨迹包目前没有总线订阅者（在 Known Limitations 中说明）。P1 工作——自动 curriculum 与 shadow/canary——是 `summary` 排序与 turn 结清事件的预定首个消费者。`command-evolution` 在触及表面之外既有的 lint 负债（更早 curator 动词中的 max-len 与非空断言，仓库级）保持不变。

# Agent Note：演进式整理器认领与清理

Status: implemented

[English](2026-09-11-evolution-curator-adopt-purge.md) | 中文

## 问题

两行整理器契约停留在最坏的手工形态——不是顺手，而是不可能。agent 创建的技能永远带着来源，无人认领路径，认领活在系统之外；归档技能无界累积，无物可删，使 `archiveTtlDays` 成为有文档无实现的字段。二者都由手工或时钟驱动，无需模型，契合安全切片的台账纪律。

## 决策

以 `adopt` 与 `purge` 扩展整理器服务，背后是两个遥测写入。`markAdopted` 把一条 agent 创建的记录转为用户主导来源，不重置时钟；缺席记录与非后台作者身份一律拒绝。`drop` 遗忘一条记录，并报告是否删有所获。整理器 `adopt` 记一条带前后 blob 的操作者台账条目，按构造单向。整理器 `purge` 删除超过 `archiveTtlDays` 的归档技能（默认零表示永不清理）：先删目录，再遗忘记录，再为每个技能记一条操作者台账条目；置顶技能跳过，无戳记录因 NaN 安全比较而保留，不可解析的目录只删记录，`dryRun` 只预览不写入。新增 `Config.archiveTtlDays` 遵循规范表格；模式下限为零而非一，因为零是指定的关闭态。

## 备选方案

- **认领的全记录恢复点。** 否决：认领只改一个字段，台账前后 blob 已捕获两边。单字段认领不值得快照。
- **清理被置顶的归档技能。** 否决：置顶保护已整理的技能不受破坏性整理。被置顶的归档计入跳过并保留，直到取消置顶；报告给出计数。
- **把无戳归档视为无限老。** 以不安全否决：一见即删颠倒了失败安全方向。缺失戳解析为 NaN，永不超过 TTL，因此损坏记录可见地累积而不是消失。
- **对缺失目录拒绝仅记录清理。** 否决：记录已经改变状态，需要记录其终结。缺失目录解析为 `undefined`，以 null 目录进入报告。

## 后果

整理器如今拥有完整的非 LLM 生命周期：自动流转、预览、快照、回滚、认领与保留。配置了 TTL 的地方，归档累积终结；别处零默认值逐字节保留旧行为。认领给后台归并一条人工认领路径，不碰其时钟与计数。回滚只覆盖流转——被认领与被清理的技能保持操作者留下的样子。

## 测试

遥测新增认领（缺席、重复认领、用户主导拒绝，以及时钟稳定）与删除（真/假）用例。整理器新增经由台账的认领与无存储拒绝、带目录删除的 TTL 清理、置顶跳过、仅记录清理与清理台账条目、年轻保留与试运行预览，以及零 TTL 与无存储的空报告。按文件 100% 在语句、分支、函数与行上成立。

# Agent Note：演进式整理器——闲置自动流转与试运行预览

Status: implemented

[English](2026-09-11-evolution-curator.md) | 中文

## 问题

技能遥测积累的生命周期状态无人推进：`active`、`stale` 与 `archived` 只写不转，整理证据逐渐腐烂，规范中的闲置触发器（`intervalHours`、`minIdleHours`）没有所有者。完整整理器（合并、备份、台账、回滚、清理）是多轮工程，但无模型的一半——带预览的闲置自动流转——可独立交付，且验证契约的试运行行直接断言它。

## 决策

在 `evolution/` 分组交付仅含自动一半的 `@deepseek-ai/dsh-evolution-curator`。`EvolutionCurator`（`ctx.evolutionCurator`）打开 `evolution_curator` 域（版本 `1`、表 `meta`、单个 `state` 行持有 `lastRunAt`），沿技能遥测应用 `active → stale → archived`：闲置时长从上次加载起算，从未加载则从播种起算，因此从未使用的技能同样在宽限下老化，而不是一见即归档。`maybeRun` 按总开关、已过周期与观测闲置放行；首次调用只播种记账并递延一个周期。`run` 返回 `CuratorReport`，列出每次移动及其理由，以及置顶、受保护名称与被排除来源的跳过计数；`dryRun: true` 只预览不写入。遥测经由 `ctx.get` 保持可选：存储缺席时，一次通过只推进记账。`surveyCandidates` 列出 agent 创建的技能及其裁决证据（路由、状态、闲置时长、使用计数，按名称排序），不写入；保留/补丁/归并的裁决另行到来。计划引用以显式 `protectedNames` 进入，直到出现计划到技能的接缝；合并裁决、备份、台账、回滚、清理、认领与落盘归档保持延期，各有 README 条目。

## 备选方案

- **从主机服务读取时钟与闲置。** 否决：二者均以调用参数到达（`now`、`idleMs`），因此通过在测试下保持确定性，无测试钩子，无隐藏依赖。
- **插件加载时播种 `lastRunAt`。** 否决：规范要求首次通过从触发点递延一个周期，而加载时刻不是触发点。只有 `maybeRun` 盖戳，因此无闲置的挂载零成本。
- **从计划包派生保护。** 否决：不存在可读的计划到技能接缝。显式名称表诚实、可覆盖、日后可重接；README 把该接缝记为延期工作。
- **与过期阈值无关的归档阈值。** 在测试中否决：更低的归档会让过期技能一见即退。`resolveConfig` 对倒置组合大声失败。
- **覆盖通过中的所有主机 I/O 故障。** 不必要：通过不做文件系统 I/O——流转走遥测，记账走域，两边都有真实覆盖。

## 后果

闲置整理如今在会话之间运行，报告可预览：Host 在启动或闲置时调用 `maybeRun`，状态界面读取 `lastRunAt`，`dryRun` 在落子前展示精确的移动。置顶、受保护与共享技能永不移动；目录外的技能记入 `custom`，而不是逃出整理。后来的切片在本次通过之上叠加了快照、台账、回滚、认领、清理与合并调查，无需改动它；剩余契约是保留/补丁/归并裁决与落盘归档。

## 测试

十个用例锁定：配置默认值与倒置阈值拒绝、启动前失败、首次播种与周期递延、禁用/新鲜/近期活跃的闲置、带理由文本与终态稳定的完整 `active → stale → archived` 旅程、从播种起算的从未使用老化、置顶/保护/排除跳过（含目录外技能）、记账盖戳的试运行纯洁性、无遥测时的记账推进，以及合并调查（含名称排序、目录外证据与无存储空报告）。按文件 100% 在语句、分支、函数与行上成立。

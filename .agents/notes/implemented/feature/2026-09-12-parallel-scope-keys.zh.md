# Agent Note: 并行作用域键

Status: implemented

[English](2026-09-12-parallel-scope-keys.md) | 中文

## Problem

[并行工具调用决策](2026-07-10-parallel-tool-call-execution.zh.md) 为每个调用只提供一个一元分类器 `isConcurrencySafe(args)`。它回答的是「这个调用能否与任意兄弟调用重叠」，而不是「它能否与*这个*兄弟调用重叠」。每次只改动一个资源的工具无法使用它：对同一路径的两次 `write` 调用各自都能安全地与无关的读调用并行，但彼此之间并不安全。这类工具只能声明自己为独占，从而放弃全部重叠，早先的笔记把这一点记为该一元契约已接受的局限。

`specs/improvement.spec.md` 第一阶段点明了缺失的契约：`defineTool.parallelScopeKey(args): string`，由原生调度器读取。

## Decision

作者可以在 `isConcurrencySafe` 旁声明 `parallelScopeKey(args)`，返回一个不透明键，用来指明该调用占用的资源。调度器按键的精确相等做比较，绝不解释键的含义。返回同一个非空键的两个调用绝不重叠；返回空串、未声明、或原始实现返回非字符串，都表示不声明作用域。两个分类器都是纯函数且同步，且只有重叠分类器对同一组参数恰好返回 `true` 时，才会调用作用域分类器。

`defineTool` 在调用带类型的分类器之前先校验参数，参数非法时不返回作用域——这类调用本就是独占的。任一分类器抛出异常都会让该调用成为独占，因此无法分类的调用绝不会加入并行池。

`ToolExecutionMode` 承载该分类结果：`{ kind: 'parallel'; scopeKey?: string } | { kind: 'exclusive' }`。`ctx.tools.executionMode(exec)` 仍是唯一的入口，因此不新增注册表 API，也不存在第二条解析路径。

调度器记录在途分派的作用域键。待启动调用的键若已被持有，就要等到当前池排空；持有者结算后，该调用在有池位空出时启动。于是同键调用按模型顺序逐个执行，并始终留在同一个分组内，而不同键与未声明作用域的调用仍会打包并行，直到 `maxParallelToolCalls` 上限。独占调用依旧构成任何作用域键都无法绕过的顺序屏障。

PTC 模式不变：一次原生 `run_code` 调用仍通过自己的串行队列分派子调用，`maxParallelSubCalls` 语义不受影响。

## 已声明的作用域

文件系统写操作会声明自己占用的资源：`write` 与 `edit` 以 `file_path` 为键，`str_replace_editor` 的每个命令都以 `path` 为键，三者都声明 `isConcurrencySafe: () => true`。键取参数经当前平台 `node:path` 规范化后的结果，因此 `./a.txt` 与 `a.txt` 属于同一作用域，而 `a.txt` 与 `b.txt` 可以打包并行。三个工具共用一个键空间，于是对同一路径的写入与编辑会串行，而不是竞态到版本过期失败。

规范化不会合并大小写不敏感的别名或符号链接，因此这类组合仍可能重叠。对 `edit` 与编辑器的受保护命令，观测守卫会以 `FS_STALE_VERSION` fail closed；而 `write` 是整文件替换，后一次调用的内容无论如何都是最终结果。

## Consequences

安全性取决于「与谁并行」的工具现在可以声明这一点，而调度器无需比较调用：工具说明自己占用哪个资源，相等性完成其余工作。

作用域键是进程本地的字符串，只在一个步骤的池内比较。它们不会跨智能体、跨步骤或跨进程串行化；键在其分派结算时释放，而不是在结果提交时释放，因此这一保证是「持有期间不重叠」，而不是调用方可以观察到的锁。

没有任何机制核验该声明。键过宽会静默串行（只损失并发，绝不会带来正确性收益），键过窄则会重新引入该工具本想避免的竞态。这与 `isConcurrencySafe` 既有的信任关系相同，也正是两个声明放在一起的原因：无法正确命名自身资源的工具应当保持独占。

模型可见行为不变。该元数据不会进入 `schemas()`、提示词或会话日志，结果仍按模型顺序提交。

## Verification

单元测试在 `packages/core/tools/tests/execution-mode.spec.ts` 固定分类契约：声明的键随并行模式返回、空键读作无作用域、重叠分类器拒绝该调用时键被忽略、抛出异常与非字符串返回都分类为独占、参数非法时绝不调用作用域分类器，且两个分类器都不会进入 `schemas()`。

调度器测试在 `packages/core/agent-loop/tests/tool-calls.spec.ts` 固定可观察行为：三个同键调用按模型顺序逐个启动，而三个不同键或未声明作用域的调用同时启动。

第一方测试固定已声明的作用域：`packages/fs/tool-fs/tests/tools.spec.ts` 与 `packages/fs/tool-str-replace-editor/tests/tools.spec.ts` 把未规范化的 `./a.txt` 写入与 `a.txt` 编辑读作同一个键、把 `read` 读作无作用域、把不同路径读作不同的键。

`pnpm run verify-type-equiv` 保证 [tools](../../../../docs/subsystems/tools.zh.md) 中的声明块与源码一致。

## Alternatives considered

**兄弟感知的分类。** 把待处理批次交给分类器，让它比较各调用。这需要跨互不相关的工具建立共享的资源标识与冲突语义，并且会让纯谓词依赖批次顺序。

**由工具在 `execute` 内部持有的互斥量。** 这会在分派之后才串行，于是池仍会启动每个调用、上限统计会把实际在等待的调用算作并行，并且循环可能因为一个慢的兄弟调用而压住已可提交的结果。

**注册表级的资源锁，并为其单独定义一套词汇。** 多一种声明类型加一个运行时句柄换来同样的效果，却让原生路径与 PTC 路径去调和两套资源模型。

**让这类工具保持独占。** 正确且已经可用，但它放弃了触碰不同资源的调用之间的重叠——而这正是催生该契约的场景。

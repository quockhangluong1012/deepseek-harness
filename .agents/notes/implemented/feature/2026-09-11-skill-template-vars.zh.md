# Agent Note：技能加载时模板变量

Status: implemented

[English](2026-09-11-skill-template-vars.md) | 中文

## 问题

技能正文既说不出自己的目录，也说不出加载中的会话：引用 `references/chapter.md` 的技能没有可移植的写法，作者只好硬编码本机路径，换台机器就坏。注册表其实握着每个技能的绝对 `SKILL.md` 路径，每次加载也都发生在已知会话中，只是没有任何步骤在模型读到正文前把二者代入。

## 决策

在 `packages/skill/tool-skill` 的两条加载路径——`skill` 工具结果与 `/name` 预注入——经由纯 `src/template.ts` 助手展开 `${DSH_SKILL_DIR}` 与 `${DSH_SESSION_ID}`，发生在共享 `renderSkillContent` 包装之前。目录从技能摘要或定义的 `path` 派生；会话 id 来自加载中的 agent 会话。其他 `${...}` 原样保留，没有值的变量也原样保留：虚拟技能没有路径，无 agent 的工具调用没有会话。`renderSkillContent` 不动，因为它属于 `dsh-skill` 服务定义接缝；展开是本包的展示决策。回放渲染无需改动，已存储的结果本来就是展开后的文本。

## 备选方案

- **在 `renderSkillContent` 里展开。** 否决：它是接缝的 canonical 渲染，其 `Pick` 契约既不带会话也不做目录派生。为单个消费者的需求拓宽服务定义不值得。
- **拒绝含不可解析变量的正文。** 否决：虚拟技能本来就没有路径，加载失败惩罚的恰恰是最不需要可移植性的技能。原样透传让每次加载都工作，作者从本来就要读的资源提示里学到这两个名字。
- **通用的 `${ENV}` 插值。** 以安全面否决：无限制的环境变量外流进模型上下文需要 `required_env` 设计（白名单、沙箱透传、网关涂黑），而不是静默 glob。双名集合按构造封闭——替换器只匹配这两个字面量。

## 后果

可移植技能如今可以在两条加载路径以同一 canonical 行为，用 `${DSH_SKILL_DIR}` 引用同目录文件、用会话 id 做诊断。虚拟技能的作者看到字面占位符，从 README 而不是加载失败里学到约束。

## 测试

十五个用例锁定：未知占位符与缺失值的原样透传、逐处替换、目录派生与虚拟技能缺席，以及两条加载路径端到端（工具结果与预注入、文件技能与虚拟技能、有 agent 与无 agent 调用）。新模块按文件 100%。本包两个既有作用域注册用例在本变更前后失败一致（已用贮藏前后对比验证），归属别处。

# Agent Note：演进式技能遥测与技能管理工具

Status: implemented

[English](2026-09-11-evolution-skill-curation.md) | 中文

## 问题

技能能力只能发现与加载指令，既记不住使用情况，也改不了内容：整理工作（过期判断、合并、删除）没有持久化证据，模型也没有文件级的技能变更路径。记忆上下文的提示早已在可见技能目录旁宣告了 `skill_manage` 工具，该工具有一个已承诺的接口，却没有背后的实现。

## 决策

在 `skill/` 分组交付两个包。`@deepseek-ai/dsh-evolution-skill-telemetry` 拥有整理背后的持久化按技能记录，位于存储域 `evolution_skill_usage`（版本 `1`、表 `records`、以技能名作键）：带时刻的使用/查看/补丁计数、创建来源、置顶、生命周期状态、合并归属与归档戳。`@deepseek-ai/dsh-evolution-skill-manage` 发布面向模型的 `skill_manage` 工具，含六种文件操作：`create` 在配置目录新建技能，`patch` 替换一处恰好出现一次的子串，`edit` 在保留 frontmatter 的前提下重写正文，`write_file` 与 `remove_file` 维护附属文件，`delete` 删除技能目录。已有技能在目录发现它的位置原地变更；随包附带与 `hub*` 技能经由共享的 `isExcludedSkillSource` 写入时决策拒绝一切变更。置顶阻止受管删除，但永不阻止补丁。遥测经由 `ctx.get` 接线，因此存储未挂载时工具照常工作；前台创建永不调用 `markAgentCreated`，因此其来源保持为用户主导。

## 备选方案

- **工具模式中的 `op` 枚举。** 否决：框架在执行器运行前校验参数，会使操作自身的强制分支在按文件覆盖率门下不可达。`op` 以普通字符串发布，由执行器在变更落点强制执行六操作集合。
- **对未知操作抛错的展示器。** 否决：`defineTool` 为回放过期已记录参数而对展示器做软包装，且展示器永不得抛错。未知操作返回 `undefined`，回退到通用渲染。
- **强制注入遥测。** 否决：管理必须可独立工作。工具在每个变更点以 `ctx.get` 解析存储，无遥测组合测试覆盖全部操作。
- **覆盖所有主机 I/O 故障。** 在创建冲突上否决：非 `EEXIST` 创建失败需要平台权限或磁盘故障，因此重抛按仓库的平台故障先例携带 `v8 ignore`。删除路径经由非空目录真实覆盖其故障分支。
- **模式填充的 `op` 默认值或静默的来源回退。** 在测试中因与前几轮相同的死分支理由否决：显式标记、显式参数与大声拒绝让每个分支都可达。

## 后果

整理从此基于观测到的使用：被动 `tools/post-execute` 观察器统计加载（它先委托，因此遥测永不改变加载结果），查看与补丁经由显式标记计数，置顶保护已整理的技能不被受管删除。模型变更即时落盘为文件，每次调用一行短结果；回滚靠调用方的版本控制。记忆上下文那轮写下的经验转技能提示，如今解析到真实工具。

## 测试

三十三个用例锁定：带随包/hub 排除的标记计数、来源、置顶、带归档戳的生命周期流转、经由带桩工具的真实工具链的观察器，以及 `skill_manage` 的每种操作与其拒绝：重复创建、未知/歧义/空子串、畸形与错配 frontmatter、越界与保留路径、缺失文件、置顶与随包删除、未知操作，以及含回放回退的展示器输出。观察器用例从手工事件发送改写为生产 `ctx.tools.execute` 路径。按文件 100% 在语句、分支、函数与行上成立。

# Agent Note: 用量图表 hover——列高亮带与按天总量气泡

Status: implemented

[English](2026-09-11-usage-chart-hover-totals.md) | 中文

## 问题

跨会话浮层里的按天堆叠图（[拆分记录](2026-09-10-dashboard-split-current-and-all-sessions.zh.md)）每天编码一个数字——当天的输入与输出 token——却一个都没有读出来。图上方窗口卡片统计的是整个范围，下方表格统计的是按模型，因此某天自己的数字只以柱高形式存在。面板的内边距也偏紧：区块、统计卡片、范围按钮、表格单元格都停在 10–12px，拆分新增区块后读起来更显局促。

## 决策

在 `packages/client/ui-usage-dashboard/src/client/display.tsx` 里把每个图表列做成 hover 读数，并在 `UsageDashboard.module.css` 里放宽仪表盘共用的内边距：

- 每一列都是贯穿图表全高的 hover 目标。被指向的列在其柱子后面获得一条半透明高亮带，并得到一个锚定到该列的 HTML 气泡，显示该桶的 `day` 及其输入与输出 token 总量。
- 高亮带最先渲染，位于柱段之下；透明命中矩形最后渲染，位于其上，因此矮列中未画出的部分与其已画出的柱段一样可 hover。指针离开图表外框时两者一并清除。
- 气泡从列中心朝更近的图表边缘展开（`data-anchor` 为 `start`/`end`），而不是以列为中心居中，因此边缘列的气泡不会超出滚动容器；`pointer-events: none` 让气泡不会截住它所报告的 hover。
- 气泡复用 tooltip 表面（`--dsw-alias-tooltip-bg` 配 `--dsw-static-neutral-bluish-00` 文字，日期行取弱化色）与既有的 `chart.input`/`chart.output` 字典键，因此没有新增 locale 条目。日期按台账自己的 UTC+7 `YYYY-MM-DD` 字符串呈现，不使用 locale 格式化日期。
- 内边距改动落在共用模块里，因此右侧 Sidebar 的当前会话正文与浮层正文保持同一套设计：区块 14px 16px，统计卡片 10px 12px、间距 10px，范围按钮 4px 12px，表格单元格 6px 8px，加载/失败区块 20px 16px。

## 备选方案

- **每列包一个 `ui-primitives` 的 `Tooltip`。** 否决：它包裹单个锚点元素，并按该锚点的矩形定位一个 fixed 气泡，因此 31 天窗口要带 31 个锚点、处理器与 ref，而且它的 label 对每个锚点是固定的。图表改为只保留一个 hover 索引与一个气泡。
- **在图表内用 SVG `<text>`。** 否决：该 SVG 用固定的 300×96 viewBox 拉伸到面板宽度，文字会随面板缩放，而两行带标签的气泡还要在 viewBox 内做逐列宽度计算。
- **每列使用原生 `<title>`。** 否决：浏览器会延迟约一秒才显示，且只渲染一行纯文本，承载不了日期与两项带标签的总量。
- **把按天数字做成新的表格列。** 否决：该表是整段窗口内每模型一行，按天列与其主题不符；图表本就是提出按天问题的地方。
- **只给右侧 tab 加内边距。** 否决：两个正文渲染同一份样式表，只改其中一个会让两个界面在没有任何契约理由的情况下分家。

## 后果

图表成了它自己的按天读数：指向某一列即可回答那天花了多少，代价是模块里多一个 tooltip 表面，以及每天多出的高亮矩形。该读数是纯指针操作——没有键盘路径，也没有触摸手势——且按天数字只有这一份：卡片统计整个窗口，表格按模型统计，因此不会有第二个界面与它产生偏差。气泡是固定在图表顶部的一行 11px 文本，因此高柱的顶端会落在它后面。更宽的内边距会压缩窄右侧栏的可用宽度，统计卡片因此在栏内多折行。

## 测试

`tests/dashboard-action.client.spec.tsx` 通过 `DashboardAction` 驱动真实浮层：打开对话框，逐个指向两个 fixture 日期，并固定高亮带的日期、气泡中该日期以键回显的总量、切换到另一日期，以及离开图表后高亮带与气泡的清空。

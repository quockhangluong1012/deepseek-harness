# Agent Note: 演进记忆上下文——简报注入器与作用域提示

Status: implemented

[English](2026-09-11-evolution-memory-context.md) | 中文

## 问题

存储的演进记忆到不了模型：作用域有了记录、经验与暂存写入，却没有简报进入请求，也没有提示指引告诉模型这些记忆何时适用。逐字复制 workspace 注入器有两处被堵死：它的摘要扫描经由 `eventAt()` 读取会话表层，而新产品代码不得调用它；演进简报还多出两个层级、一个用量头和一个容量变量，workspace 框架里没有位置。

## 决策

在 `context/` 分组、workspace 对应物之旁交付 `@deepseek-ai/dsh-evolution-memory-context`，沿用[评审器决策](2026-09-11-evolution-reviewer.zh.md)。注入器在 `agent/pre-step` 追加一条持久 `user/message`，携带 `evolution-memory` 来源（含作用域 id 与摘要）；摘要变化则替换，不变则什么也不加。摘要比较分三级——按会话的内存标记、已认领批次、经由异步会话查询面的已记录表层——稳态回合零 I/O，重启后重新解析而不重复。框架逐字遵循规范（`# Workspace memory`、目录、`Memory usage: used/cap (pct%)`、指令、经验、用户画像、逐条上下文）：先丢弃尾部上下文，再截断经验，然后在经验已清空的前提下截断画像，最后截断指令；一行通知列出每次删减。本包还注册三个提示分节与容量变量：经验转技能指引仅在可见的 `skill_manage` 工具旁渲染，作用域收窄指引插值用量变量，会话搜索提示始终渲染。不新增组合行，因此在配置行落入 `web-app` 之前，所有 profile 的行为保持字节一致。

## 备选方案

- **照搬表层扫描做摘要比较。** 否决：新代码禁止调用 `eventAt()`。标记—认领—查询三级 cascade 用零同步历史读取回答同一问题，常见情形零 I/O。
- **复用 workspace 简报框架。** 否决：规范固定了演进框架，含用量头与经验、画像层级；共用渲染器会把两套预算与两套摘要形态缠进一个函数。
- **规范里的驼峰 `{{evolutionMemoryUsage}}`。** 在提示组装器拒绝后否决：框架变量语法只接受小写名，变量以 `{{evolution_memory_usage}}` 发布，包 README 记录了该偏离。
- **`profile` 可选并默认 `default`。** 测试中否决：组合 schema 在 apply 之前填充默认值，会在文件级覆盖率门禁下留下一个死亡分支。命名空间改为必填，每个作用域键都显式具名其所有者。
- **等技能包落地再注册技能提示。** 否决：返回空文本的 provider 对组装零贡献，休眠分节今天零 token，`skill_manage` 出现之日无需改注入器即可激活。

## 后果

挂载注入器的作用域以每次变化有界的成本向每个回合展示共享知识；文件上下文在注入时重读，不可读文件行内具名。提示组装新增三个短分节与一个插值；作用域之外的会话把变量解析为 `unknown` 而不使组装失败。暂存写入与产出永不使简报失效，因为摘要排除它们。

## 测试

13 例渲染规约锁定：框架、空分节省略、闭合标签转义、删减与截断顺序及单行通知、含极小预算的精确字节上限、多字节安全、不可用文件行。瀑布规约锁定：注入/跳过/替换循环、已认领与已记录摘要路径（含表层读取失败）、拒绝与中止处理、归属缓存与移除、目录退路、双读取器的文件物化、形似消息处理、逐层级记录、释放、加载时 profile 校验。REAL 组合规约驱动生产循环与脚本适配器，断言适配器收到组帧简报、日志恰好一条演进消息、第二回合零新增、系统提示携带解析后的用量变量；记录变更会追加恰好一条替换简报，而任何作用域之外的会话一条也收不到。分节规约锁定名称、文案、技能可见性规则、用量格式化、有无注册表的组装。语句、分支、函数、行四项文件级 100%。

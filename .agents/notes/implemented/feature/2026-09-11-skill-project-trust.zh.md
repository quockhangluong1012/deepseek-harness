# Agent Note：项目技能信任门控与 Hermes 根

Status: implemented

[English](2026-09-11-skill-project-trust.md) | 中文

## 问题

项目技能无条件索引：打开目录的人会把该 checkout 的 `.dsh/skills` 与 `.agents/skills` 送进模型目录，没有操作者同意，除了禁用全部默认根也没有关闭开关。规范要求项目技能过信任门，在旁边加上 `.hermes/skills` 根，并保持非交互界面无弹窗——但信任状态、扫描器、信任命令一概不存在。

## 决策

在 `dsh-skill-filesystem` 中以显式配置门控项目发现，除一个来源字面量外不动注册表契约。`trustedProjectDirs` 列出绝对项目根（相对条目在加载时大声失败）；`projectDiscovery: false` 完全禁用项目根。不受信根不贡献任何内容，并对每个根警告一次；信任是配置，因此非交互界面继承信任，永不弹窗。`.hermes/skills` 根以 rank 150、`project-hermes` 身份加入，位于项目优先级带内，与兄弟目录共用显式信任。比较跑在解析后绝对路径上，Windows 下不区分大小写。watcher 跟随发现，因此不受信根永不被监视。入库前扫描与隔离、`trust`/`untrust` 命令保持延期，各有 README 条目。

## 备选方案

- **首次信任弹窗。** 否决：发现运行在无法弹窗的非交互界面中，而模型循环里的弹窗可能被受审模型自己回答。信任只走配置。
- **与 `.dsh/skills` 共享 rank 100。** 否决：同 rank 并列会落到提供方顺序与本地顺序，让 `.dsh` 赢得静默且依赖顺序的胜利。rank 150 让每个项目根确定有序，无并列歧义。
- **信任比较追踪符号链接。** 在 v1 否决：符号链接别名只在按解析后列出时匹配，记在比较助手上。比较时追逐链接会拿可预测规则换文件系统相关的惊喜。
- **大声阻止不受信根。** 否决：不受信 checkout 是策略，不是配置错误。一次警告点名根目录与修复办法；同一提供方实例内重复保持静默。
- **把扫描器塞进本切片。** 否决：危险 skill 规则需要专门的安全设计。受信项目技能目前未经检查直接索引，已在限制中明说。

## 后果

打开不受信 checkout 不再把它的技能喂给模型：部署方经由配置选择加入项目目录，翻转 `projectDiscovery` 即恢复仅用户加自定义的目录。没有 `trustedProjectDirs` 的既有组合在选择加入前失去项目技能——这是有意的、已由更新用例覆盖的行为变更。`.hermes/skills` 根自作者启用的那天起可用，已在同一门后。

## 测试

信任矩阵用例锁定：带 `.hermes` rank 槽的受信发现、警告一次的不受信跳过（经由直连提供方，因为注册表缓存发现）、项目发现全禁用、相对信任条目的大声拒绝，以及经由 mock `process.platform` 的双平台大小写语义。新增的每一行与分支都按文件 100% 覆盖（已对覆盖图验证）；三个符号链接用例在本机因沙箱 `EPERM` 失败，且无本变更时失败一致。

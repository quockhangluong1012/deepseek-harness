# Agent Note: P0-llm fixes batch 3

Status: implemented

English | [中文](2026-09-13-p0-llm-batch-3.zh.md)

## Problem

The full-sweep review recorded in `docs/superpowers/specs/2026-09-13-full-sweep-fixes-design.md` raised findings across the llm surface, and batch 3 of that sweep — dated 2026-09-13 — dispositioned them. Three findings were real defects or missing recorded rationale and landed as code changes in `llm-retry/src/index.ts`, `llm/src/assembler.ts`, and `command-goal`; the remaining seven were declined for the reasons recorded under Alternatives considered, so a reader does not have to re-open the review to learn why they stand as they are.

## Decision

Three findings landed as code changes:

1. `llm-retry/src/index.ts`: four bare `return` abort paths now return `undefined` explicitly with one-line comments naming the declined condition. Zero behavior change; existing cancellation tests (retry.spec.ts:953, 976) pin the semantics.
2. `llm/src/assembler.ts`: class JSDoc records the layering contract — `llm-invariant` strictly throws on malformed streams when mounted, the assembler stays total for compositions running without it. Comment only.
3. `command-goal`: local `assertNever` replaced with the shared `@deepseek-ai/dsh-util-values` import (plus `dependencies` entry and `tsconfig` reference). The local message format is superseded by the shared `unreachable variant in <context>` format; no test pinned the old text.

## Alternatives considered

**Make `always` stop swallowing downstream decisions.** Refuted: `RequestErrorAction` is the closed union `{ kind: 'retry' } | undefined` (`core/agent/src/runtime-types.ts:122`), so no fail or abort kinds exist for the finding to bite on. Decline-then-retry is the designed composition, pinned by `retry.spec.ts:728,751`, and the llm-fallback decision (`.agents/notes/implemented/feature/2026-09-11-llm-fallback.md:25`) records always-starves-fallback as an accepted trade-off.

**Bound `always`.** Already documented: the policy interface, the `llm-retry` README (cost ownership plus the `llm/retry` metric), and the `keeps always mode unbounded` test all agree on the unbounded behavior, so a bound would contradict three recorded statements of scope rather than fix a gap.

**Make `translate` strict about empty ids and names.** Pinned tolerance: `translate.spec.ts:331` deliberately pins empty-string fallbacks for lenient gateways, and an empty name fails LOUD at tool dispatch (unknown tool), never silently. Strictness would regress gateway compatibility for a silent failure that does not exist.

**Require explicit quanta instead of the `?? 1` default.** Accepted trade-off: all production constructors pass quanta explicitly or take the identity default, and the pure function documents its determinism. An interface churn across 3 providers plus tests and `.d.ts` mirrors buys nothing observable.

**Throw on foreign history in `dsh-foreign` replay.** Deliberate as-is: `foreignAssistant` (`llm-pi-ai/src/replay.ts:153`) exists to convert history WITHOUT trusting it as same-model replay, and throwing would break cross-provider replay.

**Make the process-local breaker cross-process.** Already documented: the module JSDoc, the README body, and `## Known Limitations and Deferred Work` ("Process-local breaker") all state the process-local scope, so the finding restates recorded behavior.

## Consequences

The four explicit `undefined` returns carry no behavior change, and cancellation semantics stay pinned by the existing tests. The assembler layering contract is documented rather than enforced, so compositions running without `llm-invariant` keep the total assembler. `command-goal` loses its local `assertNever` wording to the shared `unreachable variant in <context>` format, with no test to update. The declined findings leave behavior exactly as recorded — an unbounded `always` that starves the fallback, lenient `translate` gateways, identity-default quanta, replay that tolerates foreign history, and a process-local breaker — and the incremental SSE emission redesign is tracked separately (see Deferred).

## Deferred

SSE `block-end` batching is deferred to batch 7. Incremental emission is a redesign needing TTFT measurement, not a bug fix: it moved to P1 with a measurement requirement.

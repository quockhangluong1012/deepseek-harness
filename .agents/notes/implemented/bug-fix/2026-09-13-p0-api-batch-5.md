## Triaged without code change (with reasons)

- **gateway lost-wakeup: refuted.** The waiter is assigned synchronously in
  the Promise executor with no await/yield between the empty-check and the
  assignment (run-to-completion), and each queue has exactly one consumer
  (`yield*`, index.ts:424). No interleaving exists.
- **methodParameterNames fragility: accepted constraint.** SRC fallback only
  (strict Typert definitions bypass it), fail-loud with a directing message,
  pinned by signature-invalid tests, and the tsdown build does not minify.
  Generator metadata would be a redesign.
- **srcClaims staleness: refuted.** `internal/service` fires from Cordis
  `reflect.ts:333` on service implementation changes, which covers
  provide/dispose; strict definitions bypass the cache anyway, and dispatch
  re-resolves fresh — residual staleness is fail-safe in both directions.
- **anchor mutation: refuted.** `parsePatchList` parses fresh objects per call
  and the file:// anchoring is idempotent over a single base.
- **patch provenance: accepted limitation.** Index-diff misattributes only if
  mid-list inserts occur; `--dump-config` is debug output, no behavior impact.
- **permission-preset live fallback: consistent by construction.** Enforcement
  (`tool-bash:169`, `tool-pwsh:181`) reads the same live defaults, so labels
  always match effective behavior.
- **schedule latch/timer, jobs quota: accepted containment.** Latch is
  fail-safe by the schedule package's stream-is-the-only-state rule (quarantine
  would silently drop reminders; fold errors name the record); requestDrive
  coalescing cannot starve wakes (each drive re-arms the nearest target);
  stopping counts toward quota because it still holds resources, with
  teardown force-failure against wedged stops.
- **homedir, vmTimeout/timers, inspector capture, .env precedence, credentials
  reload: accepted designs.** `home` is a load-bearing protocol field (loopback
  detection, picker defaults, pinned tests); vm/timer trust stance is
  documented in-module; the inspector is a local-debug tool; inherited env
  wins by documented precedence; reload warn-and-keep is the deliberate
  fail-safe mirror of settings-file.
- **Boot sync FS, RPC scans, MIN_EVERY, release timeout, preset silence:
  accepted.** One-time small-file cold-start reads; tiny-n scans with fresh
  dispatch; 300s is an abuse-protection floor in pure domain math (the package
  has no Config surface by design); fatal-path timing; resolution-time
  fail-loud already covers the preset default case.

# Agent Note: P0-api/infra 修复，第 5 批

Status: implemented

[English](2026-09-13-p0-api-batch-5.md) | 中文

## 问题

全量清扫修复的第 5 批（`docs/superpowers/specs/2026-09-13-full-sweep-fixes-design.md`）覆盖 api/infra 部分。其中三项是有复现的现网缺陷：SDK client 中无换行的 stderr 累积会无界增长；gateway stream mux 用硬编码常量限制心跳丢失次数；frontend-static host 对每个请求都重新读取未变更的资源。该批其余的发现项，或被其所指名的代码证伪，或由刻意设计所固定，因此只做了判定而未改动代码。

## 决策

审批策略折叠游标在 batch 4 期间实现并验证，随提交 `6c28cc52a1` 发布；它已在 batch 4 的说明中总结，此处列出仅因为其发现项归属 api/infra 部分。

1. `sdk/client/src/client.ts`：无换行的 stderr 累积以 `STDERR_LINE_BUFFER_LIMIT` 为上限（64 KiB，保留最新部分）。新增 `FAKE_STDERR_FLOOD_BYTES` harness + 测试（修复前以 262,247 字节的错误失败，修复后有界通过）。
2. `api/gateway`：`websocketHeartbeatMaxMissed` Config（schema 默认 2）替换 `MAX_MISSED_HEARTBEATS` 常量并接入 `RemoteStreamMuxServer`；新增 `startMux` 辅助函数与 maxMissed=1 测试；扩展 Config 形状测试；更新 README 与 README.zh（既改了旋钮行，也改了那句过时的 "terminated at the next interval"）。
3. `host/frontend-static/src/index.ts`：fiber 作用域内按 stat 校验的资源缓存（100 条，以 mtime+size 为键），配合 etag/304 条件式服务；index 路径保持动态且不缓存。两个组合测试（etag 往返、重建后的重新校验）。同 tick 同尺寸重写导致的陈旧性已在代码中记录。

## 考虑过的替代方案

**修复所报告的 gateway 丢失唤醒。** 已证伪：waiter 在 Promise 执行器中同步赋值，空检查与赋值之间没有 await/yield（run-to-completion），且每个队列只有一个消费者（`yield*`，index.ts:424），因此不存在交织。

**针对压缩或定义改写加固 `methodParameterNames`。** 改为接受该约束：SRC 回退是唯一路径（严格的 Typert 定义不走该路径），它以带指示的消息 fail loud，signature-invalid 测试对其固定，且 tsdown 构建不做压缩。改用生成器元数据属于重新设计。

**更积极地让 `srcClaims` 失效。** 已证伪：`internal/service` 由 Cordis `reflect.ts:333` 在服务实现变更时触发，已覆盖 provide/dispose；严格定义本就绕过缓存，而 dispatch 会重新解析 —— 残余陈旧在两个方向上都是 fail-safe。

**在 anchor 变更时重新解析或复制。** 已证伪：`parsePatchList` 每次调用都解析出新的对象，file:// 锚定在单一 base 上是幂等的。

**让 patch 来源在列表中部插入时仍然正确。** 改为接受为既有局限：index diff 只在发生中部插入时归因错误，而 `--dump-config` 是调试输出，不影响行为。

**快照 permission preset 的标签，而不是读取实时默认值。** 按构造即为一致：执行侧（`tool-bash:169`、`tool-pwsh:181`）读取同一份实时默认值，因此标签始终与生效行为一致。

**在 fold 出错时隔离 schedule latch。** 改为接受其收敛方式：依据 schedule 包「stream 是唯一状态」的规则，latch 本身是 fail-safe —— 隔离会静默丢弃提醒 —— 且 fold 错误会指名相应记录。

**为 `requestDrive` 的合并加上唤醒保证。** 改为接受其收敛方式：合并不会饿死唤醒，因为每次 drive 都会重新武装最近的目标。

**把 stopping 中的任务排除在配额之外。** 改为接受其收敛方式：stopping 仍然占用资源，而 teardown 会以强制失败应对卡死的 stop。

**用不透明 id 替换 `home` 协议字段。** 不是 P0 修复：`home` 是承重字段（loopback 检测、picker 默认值、固定测试）。

**收紧 vm/timer 信任、inspector 捕获、`.env` 优先级或凭据重载。** 改为接受为既定设计：vm/timer 的信任立场记录在模块内，inspector 是本地调试工具，继承的 env 按有记录的优先级胜出，reload 的 warn-and-keep 是与 settings-file 对称的刻意 fail-safe。

**改动启动期同步 FS 读取、RPC 扫描、`MIN_EVERY`、release 超时或 preset 静默。** 接受现状：一次性小文件冷启动读取；tiny-n 扫描配以新鲜 dispatch；300s 是纯领域数学中的滥用防护下限（该包按设计没有 Config 表面）；致命路径的时点；解析期 fail-loud 已覆盖 preset 默认值的情形。

## 后果

stderr 累积被限制在最新的 64 KiB；心跳丢失上限成为部署配置（默认 2）而非常量；frontend-static 对未变更资源做条件式服务，index 路径保持动态。两项限制按设计保留：资源缓存在同 tick 同尺寸重写时可能返回陈旧字节（已在代码中记录），index diff 的 patch 来源在发生中部插入时可能归因错误，而这只影响调试输出。该批判定不改动的每一项都保留其已记录的行为，权衡就记录在紧邻的《考虑过的替代方案》中。

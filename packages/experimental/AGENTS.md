# AGENTS.md — Experimental packages

These supplement the [package rules](../AGENTS.md). The [experimental publication decision](../../.agents/notes/implemented/process/2026-09-12-experimental-publication-denylist.md) owns publication policy; the [Agent Teams package decision](../../.agents/notes/implemented/architecture/2026-08-18-experimental-agent-teams-packages.md) owns dependency isolation and promotion.

- Packages belong here only when their complete public contract is experimental or internal-only; an experimental option in a release package stays with its owning product role.
- Every package here is named `@deepseek-ai/dsh-experimental-*` and joins the release family by default: omit `private`, set `publishConfig.access: public`. Only `PRIVATE_EXPERIMENTAL_PACKAGE_DIRECTORIES` ([publication policy](../../scripts/experimental-package-policy.ts)) stay private: `private: true`, no `publishConfig`.
- Packages and apps outside this group must not name experimental packages in `dependencies`, `optionalDependencies`, or `peerDependencies`; [default-product isolation](../../.agents/notes/implemented/process/2026-09-12-default-product-experimental-isolation.md) checks transitive installs, runtime imports, and shipped compositions in CI. Experimental packages may depend on release packages and each other; tests may use them via `devDependencies`.
- Experimental status does not relax engineering, security, documentation, lifecycle, testing, invariant, or snapshot requirements.
- Publishing neither promotes nor promises stability: promotion moves it to its product-role group, dropping `experimental-` from the npm name; update every import and configuration row atomically; review its public contract, limitations, test evidence, release payload, runtime dependents, and named stable owner.

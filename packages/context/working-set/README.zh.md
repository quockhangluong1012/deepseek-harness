# @deepseek-ai/dsh-working-set

[English](README.md) | 中文

## 概述

`dsh-working-set` 把一个任务变成它要触碰的文件：按当前目标对仓库索引排序，保留目标点名了其符号的文件，再补上这些文件所 import 的文件及其测试、配置与文档，然后把结果作为取代上一份的持久快照注入。`maxBytes` 与五个按角色的文件数上限对其设界。选中结果是索引指纹与目标的纯函数，因此选中结果不变时不注入任何内容，请求前缀保持逐字节一致。

<a id="use-this-package"></a>
## 使用本包

当模型应当在每个任务开始时就知道哪些文件重要时，把本插件与 `dsh-repo-index`、`dsh-repo-map` 一起挂载；本包注入 `repoIndex`，每个会话的选中结果由该会话的工作目录与其当前目标推导而来。

```yaml
- name: '@deepseek-ai/dsh-working-set'
  config:
    maxBytes: 3072
    maxPrimaryFiles: 8
```

| 字段 | 默认值 | 含义 |
|---|---|---|
| `maxBytes` | `3072` | 完整渲染的选中文本的 UTF-8 字节上限（不含该值） |
| `maxPrimaryFiles` | `8` | 声明了目标点名符号的文件数上限 |
| `maxDependencyFiles` | `8` | 上述文件所 import 的文件数上限 |
| `maxTestFiles` | `6` | 文件名与选中文件共享词元的测试文件数上限 |
| `maxConfigFiles` | `4` | 选中文件各祖先目录中的配置文件名数上限 |
| `maxDocs` | `3` | 选中文件各祖先目录中的文档文件数上限 |

生成的[配置目录](../../../docs/config-catalog.zh.md#deepseek-aidsh-working-set)是每个可接受字段及其源码声明的完整来源。

### 模型能得到什么

在每一个合格步骤上，插件渲染选中结果并将其作为持久 user 角色消息追加；提供检索词的目标是这一步所见的最新用户撰写文本，包括这一步刚领取的消息。选中结果不变时不注入任何内容，模型继续读取上一份快照。没有工作目录的会话、没有任何符号的索引，或索引无法匹配的任务，都不注入任何内容。

### 何时选择挂载

当会话在一个工作区根目录内工作、且模型从"直接落在正确文件上"而非自行搜索源码树中获益时挂载它。当目标很少变化、源码树小到模型可以直接读取，或仅靠 `dsh-repo-map` 已足以定位时，跳过它。选中结果的消费方是模型与上下文编译器；本包不定义工具、不定义命令，也从不限制模型可以读取或修改什么。

## 理解实现

<details>
<summary>实现内幕 —— 点击展开</summary>

### 设计理念

- **目标即准入规则。** 只有当文件声明的某个符号点名了目标词元时，该文件才进入选中结果，因此索引无法匹配的任务选中的是空集，而不是全集。
- **排序沿用仓库地图。** 主要文件就是仓库地图的排序结果（`rankRepositoryMap`）中目标点名了其符号的那些，因此两个视图对"哪些符号重要、顺序如何"的判断一致。
- **其余每个角色都是推导出来的，绝不猜测。** 依赖来自索引已解析的 import 边，测试文件来自索引自己的测试边，配置与文档来自选中文件的祖先目录 —— 全部是快照的纯函数。
- **一次渲染同时服务两个消费方。** pre-step 监听器把它渲染的文本按会话存入 `WeakMap`，编译器注册处读取它，而不是再选一次。
- **按变化注入，而不是按步骤注入。** 与上一份相同的文本不追加任何消息，因此索引指纹变了但选中结果没变的步骤零成本；已经领取了同一份快照的步骤（重试，或新进程从日志恢复的会话）同样不注入任何内容。

### 源码地图

| 文件 | 职责 |
|---|---|
| [`src/index.ts`](src/index.ts) | 插件入口：配置校验、pre-step 监听器与编译器注册 |
| [`src/select.ts`](src/select.ts) | 目标词元、主要文件排序，以及依赖、测试、配置、文档四个角色 |
| [`src/render.ts`](src/render.ts) | 选中文本及其按字节的整行截断 |
| [`src/types.ts`](src/types.ts) | 按角色的文件列表与选取上限 |

### 主要流程

`agent/pre-step` 监听器先委托给下一个监听器；在拒绝或信号已中止时原样返回决定；随后解析会话的工作目录、向 `ctx.repoIndex.ensure()` 取快照，并按目标选取。没有选中任何文件时不改动决定；与上一次相同的选中结果同样不改动决定；发生变化的结果会被存入，并作为带 `working-set` 快照来源的 user 消息追加，取代上一份。

<a id="model-experience"></a>
## 模型体验

### 持久的工作集快照

#### 模型看到的内容

选中结果以一条追加的 user 角色消息到达模型，其文本就是渲染后的选中结果。首行是下面这个头部（文件数已填入），其下按角色顺序为每个非空角色给出一个块，标题形如 `primary (<count>):`，每个文件一行 `- <path>`。该消息携带来源 `{ kind: 'working-set', form: 'snapshot', sections: [{ name: 'working-set', text }], supersedes: true }`，因此它取代上一份选中结果，成为会话当前的快照。

##### 选中结果头部

```markdown
Working set (<total> files the current task is expected to touch, ranked against its objective):
```

#### Token 影响

条件性且有界：没有工作目录的会话、没有符号的索引，以及索引无法点名任何符号的任务都不注入任何内容；被截断的选中结果只保留整行，因此单次注入绝不超过 `maxBytes` 字节（默认 3072）。

#### KV Cache 影响

前缀稳定：选中结果不变时不追加任何消息，因此请求前缀保持逐字节一致、已有 KV Cache 条目继续可用；发生变化的结果追加在该前缀之后，而不是重写它。

### stable-core 工作集产物

#### 模型看到的内容

挂载了 `dsh-agent-context` 时，插件还注册一个来源：producer 为 `working-set`，kind 为 `artifact`，trust 为 `untrusted`，placement 为 `stable-core`，并使用同一个 `maxBytes` 上限；请求该来源的编译会以单个条目 `{ id: 'set', text, relevance: 1 }` 收到同一份选中文本，取自 pre-step 监听器最近渲染的文本，或按需重新选取。

#### Token 影响

条件性且有界：编译请求该来源时贡献这一个条目；会话没有工作目录、索引没有符号，或选中结果为空时贡献为空。

#### KV Cache 影响

与持久消息相互独立：只要索引指纹与目标不变，该来源就重新发布同一文本；插件只有在 pre-step 监听器渲染出变化的选中结果后才刷新它提供的文本。

## 已知限制与延期工作

<a id="known-limitations-and-deferred-work"></a>

这些限制界定了选中结果何时不合适。它们是本包当前的约束。

- **准入是词法的** —— 文件只能通过"目标词元匹配符号名或路径"进入选中结果，因此从不点名该标识符的同义词、缩写或任务描述不会为那个文件选中任何内容。
- **只有一个最新用户文本提供目标** —— 描述分散在若干条用户消息中的任务，只按最新一条（加上这一步刚领取的消息）选取。
- **只有索引的事实可被选取** —— 选取沿用 `dsh-repo-index` 的按行抽取，因此索引未识别的符号或 import 无法把文件带进来。
- **依赖只有一 import 层深** —— 与主要文件相隔两个 import 的文件不会被选中，只通过动态 import 到达的依赖不可见。
- **测试来自索引的边** —— 只有当索引把某个测试文件与某个选中文件关联起来（已解析的 import 或路径约定）时，该测试文件才会被列出，因此只通过动态方式、或经由名称不同的文件到达被测代码的测试不会被列出。
- **配置名称是固定的** —— 只有 `package.json`、`tsconfig*.json` 与 `*.config.<js|ts>` 算作配置，因此名称不同的配置文件不可见。
- **文档只来自祖先目录** —— 仓库中其他地方描述某个选中文件的文档不会被列出；当英文版存在时，`.zh.md` 译版会被去掉。
- **选中结果是上下文，不是契约** —— 没有任何机制强制模型只读取或修改列出的文件；授予该约束的变更契约是另一项能力。
- **按字节，不按 token** —— `maxBytes` 以 UTF-8 字节按整行截断，因此 token 成本随路径长度变化，而头部仍然给出完整文件数。
- **截断是静默的** —— 模型不会被告知字节上限切掉了哪些文件，只知道一共选中了多少个。
- **没有工作目录就没有选中结果** —— 头部不带 `cwd` 的会话什么也收不到，无论索引多大。
- **过期结果不会被重新注入** —— 目标停止变化时最后一份快照留在原处，因此很久之后的步骤仍看到上次变化时的选中结果。

<a id="dev-note"></a>
### 开发备注

<details>
<summary>维护者工作上下文 —— 点击展开</summary>

pre-step 监听器在计算任何东西之前先委托，因此拒绝的监听器仍然短路该步骤，已中止的信号不产生任何遍历成本。会话选不出任何文件时会删除 `WeakMap` 条目，因此失去工作目录的会话不会再发布上一份文本。

选取从 `session.deriveMessages()` 加上这一步领取的消息中读取目标，是因为领取的消息尚未出现在表层；这正是"开启任务的这一步按刚领取的任务选取，而不是按上一轮目标选取"的原因。

`renderWorkingSet` 对没有任何文件的选中结果返回空字符串，这正是让索引无法匹配的任务不至于把一条仅含头部的消息花在模型可见面上的原因。

</details>
